# InkLoom validation checklist

Run the smallest relevant checks after an edit, then run the full build when changing shared components, routing, styles, or many MDX pages.

## Contents

- Structural checks
- Visual and interaction checks
- Note-embed checks
- Deployment handoff and commands

## Structural checks

- Run `pnpm animation:styles`. Every new animation node must have a `visual-direction.json` beside `remotion/`; exact fingerprints must not duplicate another node. A repeated family is allowed only when the palette, typography, composition, surface, motion, or transition is visibly and materially different.
- When a new direction is introduced, confirm `visual-direction.json` marks its original node with `catalog.status: "featured"`, `catalog.source: "original-node"`, a valid `/inkloom/.../` route, and a `catalog.title` that names the visual style rather than the node's legal topic. Confirm the `/demo/` root uses that same style name, previews the original composition, and opens that existing MDX route; reject a legal-concept label, duplicate demo composition, or duplicate carrier.
- When a node reuses a catalog direction, confirm it records `derivedFrom` and a concrete `variation`, keeps all visual implementation local, and does not add a duplicate catalog entry unless it is intentionally promoted as a materially new direction.
- Confirm new nodes import neutral runtime helpers rather than `src/animations/shared/legal-visual.tsx`; the latter is a legacy compatibility layer.
- Confirm changed files are under the intended InkLoom area.
- Confirm every imported component exists and its props match the implementation.
- Confirm every semantic scene has an intentional density estimate using `1.2 + 0.9 * sequentialBeats + 0.35 * denseReadingGroups + 0.5 * branchHandoffs` seconds as a starting point, with `/objective/civil-procedure/04/legal-jurisdiction/?scene=mediation-confirmation` (330 frames at 60 fps, about 5.5 seconds) as the comfort reference. Check the actual delivered scene duration after playback-rate conversion. Reject a fixed 15-second target, a 20-second cap applied to the complete multi-scene composition, and any single scene over 20 seconds without explicit approval.
- Confirm local images exist and use the intended relative `./assets/...` path.
- Confirm raw legal material was first processed with `legal-marknote` in its user-supplied original file, while an already structured Markdown note was not processed again. Confirm the note and its assets remain at that original location and are absent from the website carrier.
- Confirm the explainer count follows an explicit mapping from important or difficult points to independent learning objectives. Reject a fixed numeric quota, filler nodes, and unnecessary MDX carriers. Require each chosen explainer to have a focused legal learning objective, a stable `animation.meta.ts`, a source under `src/animations/<subject>/<chapter>/<animation-id>/remotion/`, and a direct Astro/React player embed in its own thin MDX carrier.
- Confirm the published AVIF is not stale: `pnpm animation:styles` fails a node whose `public/animation-avif/<animation-id>/manifest.json` `generatedAt` predates the node's latest source commit by more than a minute — the site may be serving a render from before the last fix. When a user reports a visual defect, first compare the render they saw against the current source (capture fresh pages and diff) before reworking anything; the defect may already be fixed with only the embed or browser cache stale. After any source change, republish the AVIF set in the same pass.
- Confirm AVIF publication has not changed the original full-length video composition, video encoding/publication path, total duration, or the existing scene pagination and semantic deep-link format. Do not accept per-scene video output as a substitute for the original video.
- Confirm the MDX carrier contains only the animation component import and frontmatter. It must not contain `## 动态...` description titles (such as `## 动态判断路径` or `## 动态选择路径`) or `## 场景终帧` sections. Animated AVIF companions belong under the public asset contract, not in carrier prose.
- Confirm `$remotion-best-practices` was read before the Remotion edit and that the React Markup, Rendering, Multimedia, or other routed reference was loaded when that task required it.
- Confirm moving a note would require changing only the relevant `sourceReference` metadata field, not the animation ID or published MDX carrier route.
- For a published-node theme rewrite, diff the old and new public contracts. Require the same `animation-id`, semantic scene IDs, scene order, AVIF filenames, MDX route, and deep-link keys unless the user explicitly authorized a reference migration.
- For every new or changed non-legacy animation, require each scene in `visual-structure.json` to declare a non-empty `finalKnowledge` array and a `statefulObjects` array. Every `finalKnowledge` ID must map to one `data-final-knowledge` element in that scene; every stateful object must map to both `data-stateful-source="<id>"` and `data-stateful-terminal="<id>"`. An empty `statefulObjects` array is valid only when no knowledge-bearing object moves or transforms.
- Confirm each `data-stateful-terminal` is a visible child block, transformed outcome, or equivalent terminal representation that preserves the source object's identity and resulting legal state. Reject disappearance, a connector alone, or an unrelated summary as state conservation.
- When an existing SiYuan note was explicitly requested as an embed target, confirm `$siyuan-cli` inserted one new sibling iframe block after every requested source-point block, in source-note order. Verify the explicit mapping from source block to animation route, scene key, and scene title; do not assume only two embeds or one embed per animation.
- When Markdown iframe insertion was explicitly requested, confirm each new iframe follows the exact paragraph, list, section, or callout it explains and that surrounding source content was not moved, rewritten, or converted to MDX.
- Search changed MDX/Astro files for bare absolute site links such as `/objective/`; replace them with `/inkloom/...` or a relative link.
- Check nearby `_meta.yml` files when adding, moving, or renaming pages.

## Visual and interaction checks

- Treat Remotion page-still QA as a blocking iterative loop, not a one-time command:
  - Inspect every `SCENES` entry before rendering: `previewEndTrimFrames` is mandatory. Confirm it is `0` only when the scene has no authored exit; otherwise confirm it reaches the first stable frame immediately before the exit. Verify the embedded Player ends on that stable frame, while the full composition duration remains unchanged.
  1. After creating or changing one animation, choose exactly one capture mode for its review. Run `pnpm animation:pages <animation-id>` for stable final frames. When sustained emphasis is present or changed, run `pnpm animation:pages <animation-id> --motion` instead so its one contact sheet contains all motion checkpoints plus the stable final frame for every scene; do not routinely inspect both runs.
  2. Do not automatically add a second review run after an animation already has an approved contact sheet. Use `pnpm animation:pages` with no ID only when a shared change requires recapturing all animations; in that case, treat the newest generated sheet for each animation as its sole review sheet and do not reopen the superseded sheets.
  3. Open only `.artifacts/animation-pages/<animation-id>/<timestamp>/contact-sheet.png` for routine visual review. It must arrange every semantic scene in that animation in one sheet; a motion run must arrange every checkpoint and each scene's stable final frame in that same sheet. Use `manifest.json` to map tiles to scene IDs and frames. Do not open the individual 1920x1080 `page-*.png` files one by one.
  4. For every tile in the contact sheet, verify that the frame is nonblank and error-free; all intended teaching content has entered; no text, icon, connector, label, or emphasis appears clipped, overlapping, occluded, or outside the canvas; text remains readable; branch, sequence, containment, comparison, and causal relationships are unambiguous; colors and emphasis match their semantics; the page contains no unintended adjacent-scene content; and the legal conclusion remains faithful to the source note. The DOM occlusion audit inside `pnpm animation:pages` enforces the overlap half mechanically (`DOMOCCL` lines; `OCCLUSION` errors fail the run): at the stable frame and six motion checkpoints it rejects any pair where one rendered element covers at least 30% of a text-bearing element (45% for a graphic over text); low-opacity decoration such as watermark totems is excluded. A panel that travels over text while entering fails even though it settles clean — rework the entry motion, not just the final layout.
  4a. If and only if a tile leaves a concrete doubt, use Sharp or an equivalent image crop operation to extract a tight local region from the corresponding `page-*.png`, enlarge that crop, and inspect only the crop. Record the scene/frame and crop bounds. Never load the complete source PNG merely to zoom it, and do not crop unaffected regions.
  4b. At a 1920x1080 authoring canvas, reject focal legal concepts or primary node labels below 30 px and reject knowledge-bearing conditions, explanations, axis labels, or branch labels below 22 px. Permit 15-18 px only for non-semantic metadata such as scene numbers, English eyebrows, coordinates, and `STATION 01`. Inspect the rendered player at reduced width as well as the source code because technically compliant text can still be visually too weak.
  4c. Reject a size correction that harms the composition. Enlarged text must remain unclipped and must not crowd icons, connectors, neighboring nodes, titles, or safe zones. Prefer deliberate wrapping, rebalanced regions, freer title placement, and removal of decorative metadata over indiscriminate scaling. Preserve wording that encodes legal conditions, exceptions, roles, or relationships; do not obtain a cleaner frame by deleting knowledge structure.
  5. Mark canvas utilization as failed when the main teaching structure sits in one corner, side, or narrow band and a large unused region has no semantic, pacing, focus, reveal, or motion purpose. As a practical signal, roughly one-third or more dead usable canvas requires explicit justification. The pixel audit inside `pnpm animation:pages` enforces this mechanically on every stable frame (`UTIL` lines; `CANVAS` errors fail the run): usable-frame content coverage below 30%, any empty 2x2 grid region or fully empty horizontal band of the 4x3 grid, or a content footprint below 62% of frame width or 55% of frame height is a failure. The remedy is content enrichment, never cosmetics: fill the dead space with real teaching content — more icon-anchored knowledge rows, larger information units, added condition/exception/procedure dimensions, a comparison column or summary strip that belongs to the legal structure. Rescaling the sparse layout, stretching surfaces or padding, spreading the same thin content wider, or adding decorative filler still fails the audit and the contact-sheet review.
  6. Mark visual explanation as failed when a core rule, principle, conclusion, condition, or exception is primarily communicated by a prose paragraph or stacked full sentences. A “核心原理” box containing explanatory prose is an automatic failure. Require meaningful nodes, connectors, branches, containers, timelines, comparison lanes, transformations, or causal motion; allow only short labels, keywords, values, and one brief subordinate caption.
  7. Check whether concrete people, roles, groups, institutions, documents, measures, actions, and outcomes have useful semantic icons or compact pictograms instead of relying only on highlighted words. Reject monotonous text-led scenes when recognizable visual tokens could carry those concepts. Require a short label for ambiguous symbols and consistent icon style, scale, stroke weight, and color semantics.
  7-ic. Icon-anchor density gate (image-based recall). Reject any scene whose teaching content reads as rows or cards of colored text pills — highlight and color styling do not substitute for graphic anchors. Require every knowledge-bearing row or card to carry its own semantic icon anchor next to the label (an icon chip, pictogram, or role glyph that participates in the structure), and require each scene to render at least one large translucent watermark totem (a pictogram of roughly 90 px or more at reduced opacity) behind a panel or in a corner as the background graphic layer. `pnpm animation:styles` enforces mechanical floors per scene — at least 4 row-anchor icon instances, at least 3 distinct semantic icons, at least 1 watermark totem; a scene may satisfy the numbers yet still fail review when most rows remain un-anchored text. Reject icons pasted decoratively beside prose from counting toward the floor. An icon-titled panel whose body remains a multi-line prose paragraph still fails: segment the body into icon-anchored rows or chips so each fact keeps its own glyph. The floors are a minimum, not the standard — a rebuilt scene following the row-chip pattern typically renders far more icons than the floor.
  7a. Do not require a dominant concept icon when it does not fit the knowledge structure. Verify that each scene instead has an appropriate visual anchor, such as a concept icon, path, fork, role pair, boundary, timeline, comparison axis, or typographic sequence. Reject both missing structure and an icon forced into a scene where it adds no explanatory value.
  7b. Review typography across the complete node. Reject nodes that distinguish every key phrase only with the same color or same highlight treatment. Normally require at least three semantically assigned treatment families across a multi-scene node, such as soft highlight, thin underline, label block, stamp, or external negation, while allowing a documented simpler vocabulary when the content genuinely needs less.
  7c. Reject thick circles, crosses, or strike-through annotations that touch or cover glyphs. Confirm translucent highlights, thin underlines, and external negation marks remain readable at the initial, intermediate, and stable frames.
  7-word. Theme-vocabulary gate. Read every displayed word in the frame — scene titles, kickers, panel headers, chip labels, stamps, seals, and axis names — and reject any theme-derived coinage invented from the node's visual metaphor (such as 碑记, 碑廊, 闸门, 对照室, 两把尺). Displayed text uses the legal terms the source note itself uses; metaphor lives only in imagery (icons, backgrounds, totems, composition, motion), never in the text layer, so recall attaches to the real terms instead of competing coinages.
  8. Verify that icons participate in the teaching structure or motion as nodes, actors, targets, causes, results, or persistent carriers. Do not count decorative icons, borders, colored keywords, oversized text, or symbols pasted beside prose as visual explanation or valid canvas utilization.
  9. Mark any plain table or table-like grid as failed, including a source table restyled with colors, icons, rounded cells, or row-by-row entrance animation. Require the comparison to be re-authored as lanes, grouped modules, axes, relationship maps, branches, or progressive transformations where layout and motion explain the difference.
  10. Mark slide-stack choreography as failed when each scene independently resets, enters, waits, and exits without a meaningful carrier or conceptual reason for the cut. Adjacent scenes must preserve the viewer's mental model through a shared node, connector, color role, spatial current, camera path, or visibly caused handoff when legal semantics permit it.
  11. Mark idle or decorative motion as failed when wobble, breathing, floating, pulsing, drifting, or looping effects continue without revealing, comparing, transforming, connecting, causing, or handing off information.
  12. Mark choreography as failed when elements enter simultaneously, in arbitrary source order, or with identical card-grid motion that ignores reasoning hierarchy. Verify that prerequisites lead consequences, rules lead exceptions, and the most important distinction receives the first or strongest movement.
  13. Verify that key results receive a readable still hold and that transitions use a restrained, consistent vocabulary. Reject uncaused direction reversals, ping-pong movement, random zoom/rotation, and novelty transitions that do not communicate a conceptual change.
  14. Reject motion that creates false legal meaning: unsupported morphs suggesting identity, nesting suggesting inclusion, arrows suggesting causation or direction, or animation order suggesting priority or procedure that the source does not establish.
  15. If any contact-sheet tile or targeted crop fails, fix the composition, scene timing, information design, choreography, or shared visual system and rerun the affected animation. If the fix touches shared animation behavior or tokens, rerun `pnpm animation:pages` for all animations. Continue until the single contact sheet for each animation passes and every requested local crop resolves its specific doubt.
  16. Use `--at <0..1>` only when the default stable frame at `0.82` is not the scene's intended complete teaching state. Record why a different ratio is correct; never use it to conceal an animation defect.
  17. Mark focal emphasis as failed when an important rule or connecting factor is distinguished only by text color, bold weight, solid fill, or border color. Require at least two nearby semantic channels and confirm the icon, locator, annotation, connector, enclosure, or motion cue clearly belongs to that exact phrase.
  18. Mark the stable or final frame as failed when an authored summary bar, subtitle, conclusion card, badge, or other overlay covers, intersects, crowds, or visually suppresses any teaching node. Verify the authored composition with player controls visible and keep essential content outside the bottom control-safe zone.
  18a. Compare each scene's stable final frame with its `finalKnowledge` inventory. Reject the frame unless every declared item is simultaneously present, fully visible, inside the authoring canvas, and free of unintended overlap or occlusion. Earlier appearance during motion does not satisfy final-frame completeness.
  18b. For every `statefulObjects` entry, trace the source marker through motion to its terminal marker. Reject any path where the object fades out, exits, or enters a container without leaving a visible child block or transformed result that preserves both identity and legal state.
  19. For a scene with a long stable phase, verify its primary focal rule either retains one restrained semantic attention cue or uses deliberate stillness for a documented climax. Reject motion applied to the text baseline, more than two competing persistent cues, continuous scale/opacity breathing, or movement that has no legal meaning.
  20. Choose `pnpm animation:pages <animation-id> --motion` as the animation's single capture mode whenever persistent emphasis is added or changed. Inspect its one contact sheet containing the three motion checkpoints plus the stable final frame for every scene: the teaching layout must remain stable and readable, the final frame must contain the complete declared knowledge inventory, and at least one authored focal cue changes phase, position, or progress where sustained emphasis is intended. If motion QA becomes necessary only after a stable-sheet review, the motion sheet supersedes that earlier review; do not load both sheets as separate evidence.
  20a. Verify scene timing against content density at the delivered playback rate. Compare ordered reasoning beats, dense reading groups, branch handoffs, and final-result hold with the 5.5-second mediation-confirmation reference. Reject dead time, rushed reading, a mechanically padded 15- or 20-second scene, an unapproved single scene over 20 seconds, or any speed-up that makes the reasoning difficult to follow. Do not fail a complete composition merely because the sum of its valid scenes exceeds 20 seconds.
  20b. Inspect stable-frame content density. Density is two-sided. Reject paragraph-dependent scenes, competing reading paths, small teaching islands surrounded by purposeless empty canvas, and decoration added only to simulate density; require the visible actors, conditions, actions, relations, results, and exceptions to justify the occupied space. Reject an overstuffed frame just as firmly: a pure stacked-list scene, text pushed below the size floors to make room, or content wedged into the control-safe zone fails. The structure audit caps a scene at 8 declared `finalKnowledge` ids; when a topic carries more than that, paginate actively — split it into additional focused scenes, each with its own structural anchor and declared knowledge inventory, so the animation's scene count grows instead of any single frame craming a list.
  21. Check the rendered node against its `visual-direction.json`: one MDX node should read as one coherent visual language, while a neighboring node should visibly avoid the same background, typography, palette, headline placement, surface, and primary motion fingerprint.
  21a. For a claimed new theme or complete rewrite, reject a palette-only reskin. Confirm material changes in typography, composition grammar, surfaces, spatial rhythm, icon treatment, motion vocabulary, or transitions while the legal meaning and stable public references remain intact.
  22. For every new featured direction, open `/inkloom/demo/` and verify its preview uses the original composition, its style label matches `catalog.title`, and its link opens `catalog.route` rather than a demo-only clone. Fail the entry if its displayed name is the legal topic, node title, chapter heading, or scene title instead of a reusable visual-style name.
- Do not proceed to publishing or report the animation complete while any scene is absent from its animation's single contact sheet, any contact-sheet tile is defective, or any targeted crop remains unresolved. Individual full-resolution source pages do not require routine inspection.
- After the page-still loop passes, verify the animated AVIF set before building:
  1. Follow [animated-avif.md](animated-avif.md) and run `pnpm animation:publish-avif <animation-id>` after inspection of the PNG QA captures. Do not hand-build the public directory or manifest.
  2. Confirm `public/animation-avif/<animation-id>/` contains one q45/CRF35 animated AVIF named `<scene-id>.avif` for every existing semantic scene plus `manifest.json`; no numeric-only or title-derived filename is allowed, and no per-scene video is generated by this step.
  3. Confirm the manifest records animation and composition IDs, generation time, `format: "animated-avif"`, `quality: 45`, `crf: 35`, 2560x1440 dimensions, source/target fps, `loopCount: 1`, and exact scene ID/title/frame range/frame count/duration/file-size mappings.
  4. Re-open every file with FFprobe and an AVIF-capable animated-image reader, and verify frame count, dimensions, frame timing, and loop count programmatically. Use the animation's single all-scenes contact sheet for routine visual evidence. If decoded media creates a specific visual doubt, inspect only a tight crop from the affected frame rather than loading every first/middle/final frame at original resolution. Reject blank frames, smeared text, broken connectors, color hierarchy changes, or an exit-tail final frame.
  5. Confirm the shared player maps each unchanged semantic scene ID and page number to its original video range and matching AVIF, remembers the media tab, and exposes working replay, infinite loop, copy Markdown, copy image, and SiYuan script actions. A changed page order/range, split replacement video, missing asset, stale manifest, static AVIF, native `<img>` pause claim, or restored final-frame carrier block is a failure.
- Inspect the page at narrow and wide widths.
- Verify tables do not overflow unexpectedly and flow diagrams remain legible.
- Test memory challenge: toggle the checkbox, confirm `.answer-node` blur, and confirm hover reveal.
- Test `trigger-link-1` and `trigger-link-2` hover emphasis when the page uses `VisualFlow`.
- Test the embedded Remotion player and animated AVIF surface at narrow and wide widths; verify scene navigation, playback, mode persistence, replay/loop behavior, copy actions, image loading, aspect ratio, and reduced-size readability.
- Open every scene-specific iframe URL and verify `?scene=<key>` selects the expected visible page number and title. Test repeated uses of the same route with different scene keys independently; an invalid key silently falling back to page 01 is a failure.
- Check PageTitle quick actions, floating TOC, and any widescreen layout override touched by the change.

## Note-embed checks

- No-stacked-embeds gate: after every SiYuan or Markdown image insertion, re-read the edited region (`siyuan block children` per edited parent, or the file itself) and verify that no two image blocks are adjacent siblings, each image immediately follows the most precise block that states its point, and no image sits against another image with only blank space between. A stacked pair is a failure; fix it by re-anchoring each image to its own smaller text block, or stop and ask when the source has no finer blocks.
- Require every new player scene to expose a unique, stable, descriptive kebab-case ID. Verify durable iframe URLs use semantic keys such as `?scene=first-instance`; allow displayed numbers such as `?scene=02` only for unmigrated legacy animations. Do not append prose or punctuation to the key.
- Require verified `https://inkloomer.github.io/inkloom/.../?scene=<key>` URLs for durable SiYuan, portable Markdown, or published Markdown embeds. Never use branch, preview, or repository URLs.
- Allow `http://localhost:4321/inkloom/.../?scene=<key>` only for an explicitly requested temporary pre-publication workflow. Record every temporary iframe and do not report the note portable, published, or finished until its host is replaced and reverified.
- Read each inserted iframe block and nearby siblings after writing. Confirm knowledge-point order, exact host, route, scene query, visible scene number, and scene title.

## Deployment handoff

- After the production build passes, commit and push the changed page, player, Remotion source, animated AVIFs/manifests, and SiYuan controller together. The `main` branch deploys to GitHub Pages.
- Confirm the deployed page at `https://inkloomer.github.io/inkloom/<page-route>/` before reporting it as uploaded. The page itself is the embed target; do not hand the user iframe markup to paste manually.

## Commands

```bash
astro dev --background
astro dev status
astro dev logs
astro dev stop
pnpm animation:pages <animation-id>
pnpm animation:pages <animation-id> --motion
pnpm animation:pages
pnpm animation:publish-avif <animation-id>
pnpm animation:publish-avif
pnpm build
```

Use page-still QA first, then the dev server for responsive route and interaction checks. Use `pnpm build` as the final production-oriented gate; capture the first actionable error instead of hiding it behind a generic failure summary. Report the inspected artifact directory and any non-default capture ratio in the handoff.
