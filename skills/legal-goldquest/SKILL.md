# Legal GoldQuest

把原始法考材料变成**可扫描、可复习、可回溯**的笔记。核心方法是：先理解原解析，再选择最贴合内容的结构；用稳定的颜色把人物、概念、规则、例外和法律效果变成视觉索引。不要为了版式改写法律内容。

## 工作流

1. **锁定边界**：识别章节层级、题号、题干、全部选项、出处、答案、解析、法条、表格和图片。建立“必须保留”清单；任何原文事实、推理链或法源都不能因精简而消失。为每题保留或生成稳定的 `custom-qb-id`，并确定一个或多个考点 ID。若对应 `20-整理` 内容旁存在 `.topic-map.json`，优先复用其中已经回读验证的 `current_topic_id`，不要为同一考点另造近义 ID。
2. **先做语义色谱**：在每题或同一知识组开始前，建立 3-5 个颜色映射；多主体时扩展到 5-7 个。相同人物、机构、客体、概念和对比状态在全文使用同一颜色。答案与解析每 1-2 句至少出现一个短颜色锚点；颜色是阅读索引，不是装饰。详见 [`references/color-system.md`](references/color-system.md)。
3. **选择内容结构**：保留原解析已清楚的顺序；只有在确实降低认知负荷时，才改成时间线、程序步骤、要件判断、主体关系、原则/例外、因果链或逐项判断。Callout 可以承载任何具有独立语义属性的内容，不与法条、陷阱等固定类型绑定；表格、子列表、颜色、引述、Mermaid 和其他样式同样由真实信息关系决定。不要固定生成“争点、规则与法源、事实涵摄、选项辨析、命题思路”，也不要用近义词伪装同一模板；`命题思路` 只有原文讨论出题意图时才保留。需要判断排版强度时读取 [`examples/style-calibration-145.md`](examples/style-calibration-145.md)，只参考阅读密度，不复制其结构。
4. **做语义排版**：长句按独立的适用范围、判断对象、分支结论或法律效果拆成子列表；前提、行为要求、程序和结论若共同构成一个规则，保持同一项。避免超长列表：超过 5 个同级项目时，优先按人物、阶段、条件、后果等语义分组，再用短子列表承载分支。详见 [`references/format-playbook.md`](references/format-playbook.md)。
5. **写入题目考点引用**：题目标题紧后写一个 IAL，以 `custom-qb-question-topic-ids` 保存英文逗号分隔的一个或多个考点 ID。它必须与 `custom-qb-id` 同处一个 IAL；只表达“题目引用哪些考点”，不声明普通笔记的提供方身份。
6. **输出并复核**：题面先于答案，保证第一次作答体验；每道题都必须独立拥有 `###### 答案与解析` 标题，并把 `custom-qb-section="solution"` 直接附着在可见答案行后。Damophus 根据题目 IAL 中的 `custom-qb-answer` 和这个答案区 IAL 隐藏原文答案，不生成 HTML 遮罩。解析中再使用结论色、状态色和高亮；凡是存在多个独立主体、条件、阶段、例外或法律效果，必须选择一种能显式表达关系的结构，例如统领句加语义子列表、阶段小标题、小表或性质准确的 Callout，不能只堆平级大白字或只加粗。输出尚未完成，直到 GoldQuest 自带验证器以 `--strict` 返回退出码 0；不得改用 MarkNote 验证器、通用 Markdown 检查或人工目测替代。验证通过后再人工核对源文完整性、颜色一致性和结构是否有内容依据。

## 题目边界

每道题使用以下最小骨架；解析内部可以更短或更丰富，但不得缺少边界：

```md
##### 1.
{: custom-qb-id="civil-gold-2020-001" custom-qb-question-topic-ids="civil-contract-validity,civil-good-faith" custom-qb-answer="A"}
* 题干
    - [ ] A. 选项
    - [ ] B. 选项

###### 答案与解析
- 正确答案：A。
{: custom-qb-section="solution"}

- 依据与推理，按原解析顺序保留。
```

- 题干使用一级列表；选项使用全部未选中的任务列表。题面不得出现 `==高亮==`、答案性结论或状态色。
- `###### 答案与解析` 后第一块必须是可见答案行，下一行立即写 `{: custom-qb-section="solution"}`。该 IAL 所在块及后续内容属于答案区；题目 IAL 中的 `custom-qb-answer` 供插件隐藏和判分。
- 不生成 `<div><style>…</style>答案…</div>` 等悬停遮罩。Damophus 的“隐藏原文答案”负责显示控制，Markdown 只保留答案文字和 IAL 语义边界。
- 普通题干不放进代码块。只有原材料确实要求逐字保留换行/符号时，才把成对的 ```md 围栏放在 `> ` 引述块内。
- 解析完整保留：可以断句、加粗提示词、加颜色和拆列表，但不能删除法条、事实、理由或推理步骤。
- 解析结构最低要求：若解析含有两个以上可独立复习的判断分支，按内容选择“统领句 + 4 空格缩进子列表”、阶段小标题、3×3 以内的小表或性质准确的 Callout；超过 5 个同级项目时必须先按语义分组。仅把整段拆成多个 `-` 平级项目，或只给少数词加粗，均不算完成语义排版。

## 考点 IAL

`custom-qb-question-topic-ids` 是题目到 Topic Index 的可移植引用。每道题都必须声明；多考点用英文逗号分隔，顺序按本题判断链中的主要程度排列。

```md
##### 108.
{: custom-qb-id="civil-gold-2020-108" custom-qb-question-topic-ids="civil-property-good-faith-acquisition,civil-property-registration"}
```

- 每个 ID 使用小写 ASCII kebab-case；同一 IAL 内不得重复。
- 可以自由增加或删除考点；同步时由接收方选择 `merge` 或 `diff`，GoldQuest 不维护数据库行 ID、块 ID 或关联列 ID。
- 已有笔记的 `.topic-map.json` 是本地考点词典；只读取 `action="skip"` 且 `current_topic_id` 已验证的映射。标题含义不一致或清单处于待应用/部分失败状态时，停止自动复用并报告冲突。
- 不使用 `custom-qb-note-topic-id`、`custom-qb-role`、`custom-qb-topic-id` 或旧的 `custom-qb-topic-ids`。属性名本身已经区分题目引用方向，无需额外 `role`。

## 格式决策

- **列表**：只在项目能分别回答、分别复习或代表独立分支时拆分；每一级缩进 4 个空格并紧跟 `- ` 或 `1. `。因果、条件、递进关系使用子列表表达，不把每个标点都变成项目。
- **表格**：只用于确有对比/映射价值的内容，优先控制在 **3 列 × 3 个数据行以内**；更大内容按语义拆成多个小表或改用列表。原文表格必须保留其表格性质，不能转成 Callout；单元格内用 `<br />` 分开并列规则，并保留合并属性。
- **Callout**：只承载有明确属性的独立内容：`TIP` 记忆技巧，`NOTE` 法条/背景，`IMPORTANT` 统领性结论，`CAUTION` 陷阱/例外，`WARNING` 禁止或严重后果。普通解析使用标题、短段和列表；不得用伪 `📌[...]` 标记。
- **其他格式**：按语义分工使用 `**加粗**`、*斜体*、`==短高亮==`、`~~删除线~~`、行内代码、下划线、分隔线、emoji、图片引用和 Mermaid。删除线用于排除旧路径或错误选项，高亮用于最终判别词，行内代码用于属性名、ID、精确法条用语或必须逐字识别的短语，下划线用于标出当前比较轴；不要让同一短语叠加多种主强调。较长解析不能始终只有粗体和颜色，至少选择一种有真实语义用途的辅助样式。完整分工见 [`references/format-playbook.md`](references/format-playbook.md)。Mermaid 只表达确有顺序/关系的图，不替代法律正文；InkLoom 动图或图片只在来源已有、或用户明确要求时保留并放在对应知识点旁。
- **HTML 辅助块**：必要且合适时可以使用 `> ```html` 代码块辅助说明 DOM、IAL 关系或结构示意；HTML 代码块必须由一个外层 `<div>...</div>` 包裹，不能裸放 `<span>`、`<table>` 或散落标签。答案显示只使用题目 `custom-qb-answer` 与答案区 `custom-qb-section="solution"`，HTML 代码块不承担答案隐藏。普通 Markdown 优先，HTML 不能替代题面、解析或法源。

## 颜色硬规则

颜色必须直接挂在加粗文本后：

```md
**甲**{: style="color: var(--b3-font-color10);"}
**关键短词**{: style="color: var(--b3-font-color数字); background-color: var(--b3-font-background数字);"}
```

先建立词典，再输出正文：例如甲=10、乙=8、第三人=11、规则/法条=10、成立/有效=8、例外/限制=5 或 12、禁止/无效=13。一个词在同一题或同一组题中不得换色；对比双方使用稳定的成对颜色。颜色锚点优先控制在 2-6 个可见字符，只有不可拆的完整制度名可以放宽到 8 个字符；标点放在样式之外。只标记决定选项正误的主体、时间点、条件、制度或结论词，不把“谁 + 做什么 + 结果如何”一起染色，也不给连接词、整个分句、整句或整段染色。题面只允许中性主体/客体色，答案与解析才允许结论和状态色。

颜色编号限定为 2-13，完整语义表见 [`references/color-system.md`](references/color-system.md)。如果答案与解析出现连续三句无颜色锚点，视为未完成，必须回到第 2 步修复。

## 完成门禁

- 必须运行 `python -X utf8 skills/legal-goldquest/scripts/validate_output.py <output.md> --strict`，并取得退出码 0 后才可交付。门禁逐题检查答案标题、客观题 `custom-qb-answer`、`custom-qb-section="solution"` 边界、旧 HTML 遮罩、颜色锚点长度、解析颜色密度和多分支结构；不能用 `legal-marknote/scripts/validate_output.py`、仓库通用检查或无 `--strict` 的命令替代。缺少题目 ID、缺少考点引用、重复/非法考点 ID 或混入笔记提供方属性时，门禁必须失败。
- 有源材料文件时追加 `--source <source.md> --require-source`，检查图片、表格、标题和 SiYuan 合并属性。
- 修复所有错误并复核告警；人工确认：题面未泄露答案、答案区 IAL 紧邻答案行、解析未删减、颜色只落在关键短词且词典一致、列表按语义分组、表格不超过 3×3（或已合理拆分）、Callout/图示确有内容依据。
- 输出只包含整理后的内容，不添加开场白或结尾总结。
