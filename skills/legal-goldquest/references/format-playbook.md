# 结构与格式决策

## 从解释选择结构

先问“读者需要沿哪条关系理解？”

- 时间先后决定判断：用时间线或阶段列表。
- 行为有前提、程序、后果：用一条规则链，必要时把独立分支放进子列表。
- 多个主体互相影响：先建立主体关系，再写各自法律效果。
- 原则有明确例外：用两列以内的小表或“原则 → 例外 → 后果”列表。
- 原文逐项判断选项：用“选项 → 判断 → 决定性理由”；原文不是逐项分析时不要强行表格化。

不要为了凑齐标题而新增空泛栏目。每个标题都必须准确概括紧随其后的原文内容。

格式没有固定栏目，也不存在“法条只能进 NOTE”“陷阱必须进 CAUTION”之类的绑定。Callout、表格、子列表、阶段标题、引述、可视化、颜色、高亮和斜体都用于降低扫描负担。低复杂度解析可以克制；中等及以上复杂度默认进入丰富型，并必须把一个实质 Callout 放在它实际支持的规则节点旁。复杂推理必须由可编辑 Mermaid 承担主线；中等复杂度可在 Mermaid、`div` 包裹 HTML 或静态 SVG/PNG 中选择。不能为了显得丰富而重复同一信息。

题面本身先按语义拆成三层：H5 标题保留题号和来源已有的题型/考点标签，`**题干**` 独占一行承载共同事实，`**问题**` 独占一行承载问句。多小问放在“问题”下的缩进有序列表，每个小问独占一行；共同事实不能与 `（1）`、`（2）` 等小问继续拼在同一行。纯问句题可以省略空题干，但不能把完整题干塞回标题。

## 逐项辨析契约

只有解析确实按 A、B、C、D 等选项分别判断时才进入本分支。每个被分析选项都是一个独立复习单元，按以下完成标准处理：

1. **解析主架即逐项辨析**：若原解析以两个或以上“语义父项 + 子规则”组织，父项承担层级、比较轴、法条归属、交叉记忆钩子和整体结论。这些父项应作为**解析区内的列表父项**保留（使用 `--source` 时 `E633` 要求源解析父项仍以标题或列表父项出现在答案区），对应的选项回放直接嵌套其下共享文字。**不设独立的 `规则地图`/`知识地图` 预陈述小节再在选项解析里简单重复一遍**（`E816`）——完整知识点直接放在每个选项的解析里，读者从选项解析即可获取全部相关知识。**删除任何预陈述小节都是"先融合后删"**：删除前必须把其中的每条规则、要件、法律效果、例外和涵摄逐一融进对应选项的解析；融不进任何选项的独特规则以 `> [!NOTE]` Callout 或 Mermaid 节点保留。**禁止整段删除而不迁移**——规则地图/推理里的知识是必须保留的内容，不允许一口气删掉一大段（`E816` 的完成条件是内容迁移完成后的移除，不是丢弃）。
2. **完整复写**：保留选项标签和完整原文，包括主体、限定词、否定词、例外、时间、数字与法律效果。可以插入 Markdown 或思源 IAL 标记；去除新增 Markdown 和 IAL 标记后，文字必须能与题面原选项逐字对应。只写 `A 项`、摘录半句、换成近义概述或使用省略号均未完成。完整选项回放行属于原文引述，不受普通解析行 42 字门禁；紧随其后的理由仍须按语义拆行。
3. **原文内标注**：标记必须直接落在原选项内部决定正误的最小片段上。错误项使用 `❌` 表示排除，**必须用 `~~删除线~~` 划掉决定正误的片段**——被偷换的主体、条件、程度、时点或法律效果；只给整个选项上色不算标出破绽（`E631` 拒绝颜色代替删除线）。**删除线不得整项横扫**：整项删除线会淹没破绽（`E646` 拒绝），只有在整项命题本身就是错误对象时才可整项划线。正确项使用 `✅` 表示保留，并用 `==高亮==`、短颜色锚点或下划线圈出破题词。emoji 只说明判项结果，不能代替原文内标注。
4. **理由对位并融合**：紧跟一条短理由，说明被标片段为什么成立或错误，以及应替换、补充或对照的规则。理由必须解释标记，不能另讲一套无对应关系的知识点。理由本身必须含主体、条件、规则或法律效果中的实质信息；去掉“破绽/依据/A 项/正确/错误/排除/当选/综上”后仍须留下可独立复习的法律命题。`由综合推理可知`、`本项应排除`、`说法正确，当选`、`综上答案为 BC` 均是空解析，删除线、颜色和答案复述不能使其合格。逐项回放完成后不再另建“综合推理”区：共享规则直接写进对应选项的解析里（不另设独立规则地图，`E816`），选项专属涵摄直接放在选项下，最终结论就地收束。

规则地图与逐项回查可以写成两层，避免用选项字母吞掉原有框架：

```md
- **组织层级地图**
    - **一高＝组成部门**
        - 设立、撤销由全国人大及其常委会决定。
    - **中间层级＝直属机构**
        - 设撤并由国务院决定。
- **逐项回查**
    - ❌ A. 国家市场监督管理总局的设立要经过~~全国人大常委会批准~~。
        - **破绽**：总局属于直属机构，其设撤并由国务院决定。
```

正例保留完整选项，并让读者先在原文中看见破题位置：

```md
- ❌ A. **要约**{: style="color: var(--b3-font-color10);"}一经发出，~~即不得撤回~~。
    - **破绽**{: style="color: var(--b3-font-color13);"}：`即不得`把规则绝对化；撤回通知先于或同时到达受要约人时，可以撤回。
- ✅ B. **承诺**{: style="color: var(--b3-font-color11);"}在==到达要约人时==生效。
    - **破题点**{: style="color: var(--b3-font-color8);"}：抓住“到达”，再核对承诺通知的到达时间。
```

反例 `❌ A 项错误，因为要约可以撤回` 同时丢失完整原选项和原文内破绽标记，不能交付。

输出验证器以 `E630` 检查完整回放，以 `E631` 检查判项符号及原文内标记，以 `E632` 检查紧邻的缩进理由；带 `--source` 重整已有解析时，`E633` 检查规则地图是否仍是结构化节点。四项只能验证结构可观察事实；标记与理由在法律语义上是否真正对位，仍由人工复核。

## 样式语义分工

- `**加粗**`：小标题、判断对象和局部提示词；颜色只能直接附着在这种短粗体后。
- `==短高亮==`：答案、最终法律效果或决定正误的 2-6 字结论，不高亮解释过程。
- `~~删除线~~`：已经排除的选项、旧路径或不适用结论；删除线后必须紧跟排除理由，不能只做装饰。
- `<em>斜体</em>`：只用于少量补充口径或不承担结论的轻旁注。加粗固定使用 `**foo**`；斜体不使用 `*foo*` 或 `_foo_`，加粗不使用 `__foo__`。
- 行内代码：`custom-qb-answer`、考点 ID、固定属性值，以及确实需要逐字识别的法条短语；普通法律叙述不用等宽样式。
- 下划线：用 `<u>比较轴</u>`，或在需要颜色时用 `<u style="color: var(--b3-font-color10);">比较轴</u>` 标出当前正在比较的时间、主体或程序维度；同一段最多保留一个主要比较轴。不要写成 `<u>比较轴</u>{: style="..."}`，该形式会被门禁拒绝。
- 背景色签：只给 2-6 字的最终结论、关键时间点或核心条件增加 `background-color: var(--b3-font-background数字)`；可以单独使用，也可以和同编号前景色组合。必须先写 `**加粗文本**` 再紧跟 IAL。中等及以上复杂度至少使用 3 个，不能给整句或普通主体铺底。
- 判项符号：逐项辨析按上面的契约使用 `✅` 或 `❌`，并把删除线、高亮、颜色或下划线直接落在完整原选项的决定性片段上；没有逐项判断时不强加。

一个短语只承担一种主强调；前景色和同编号背景色共同构成一个颜色锚点，不算机械叠加。颜色已经承担人物身份时，不再给同一词叠加高亮或删除线。中等及以上复杂度必须在高亮、斜体、删除线、行内代码、下划线中至少使用 4 类；低复杂度题不要求凑齐。斜体不是必选项，并应低频使用。样式必须有真实分工，不能在同一句上机械叠加。

## Emoji 语义路由

emoji 用于让规则地图和解析区更易扫描，不替代文字、颜色、理由或法源。中等及以上复杂度的解析至少使用一个与实际法律关系相称的 emoji；`✅/❌` 只表示选项对错，不计入这条覆盖。位置由修饰范围决定：标签前用于分组，关键短语旁用于提醒规则节点，结论句末用于回指该完整判断。emoji 选择开放，下表只是常见角色示例，不是受控词表。

| Emoji | 法律学习角色 | 示例标签 |
| --- | --- | --- |
| `📚` | 法源、法条、权威依据 | `- 📚 **法源依据**` |
| `🧭` | 程序阶段、路径、时序 | `- 🧭 **审查路径**` |
| `🧩` | 构成要件、组成部分 | `- 🧩 **成立要件**` |
| `⚖️` | 法律评价、裁判或效力判断 | `- ⚖️ **效力判断**` |
| `⚠️` | 例外、限制、风险 | `- ⚠️ **例外边界**` |
| `↔️` | 对比、区分、相反规则 | `- ↔️ **规则对比**` |
| `🔍` | 审查焦点、破题点 | `- 🔍 **破题焦点**` |
| `⏳` | 期限、先后顺序、时点 | `- ⏳ **时间节点**` |

一个 emoji 应对应一个实际角色。两个角色共同支配同一范围时，可以按顺序组合，例如 `🧭⚠️ **程序风险**`、`**法源** 📚 与 **效力** ⚖️`、`**效力区分** ↔️`；也可以使用表外 emoji，只要其含义能由紧邻文字直接读出。避免无语义的堆叠。emoji 不进入题面、原选项、来源标题、代码围栏或题目 IAL；它只放在围栏外的解析结构中。

## 长列表转换

列表服务语义，不服务标点或字数。先把原解析还原成完整命题，再按“主体、适用范围、条件、程序、例外、法律效果”寻找分组轴。每个列表项必须是完整规则、完整事实涵摄或可独立复习的分支；以逗号、顿号结尾的残句必须与相邻项重新合并。`推理主线`、`推理环节 2`、`分析步骤 3` 只记录生成顺序，不提供检索意义，必须改成真实内容标签。

**段落父项化**：当解析连续出现两组或更多“一个统领文本块 + 2–3 个同级短列表项”时，不要把统领句作为无结构能力的普通段落悬在列表上方。把每个统领文本块改成一级列表项，把它统领的 2–3 项整体缩进一级作为子列表；后一组与前一组父项同级，形成一个连续整体。统领关系由语义决定：文本块必须能概括、限定或引出紧随项目；独立结论、跨组过渡、承上启下说明或不支配后续项目的正文仍保留为段落。例：`适用情形：` 段落 + 三个顶级项目，随后 `法律后果：` 段落 + 两个顶级项目，应写成 `- **适用情形**` 下缩进三个子项、紧接 `- **法律后果**` 下缩进两个子项。

## 行长与图解

- 普通解析行最多 42 个可见字符。超过时保留一句统领短句，再按“条件 → 判断 → 后果”或实际关系拆成子列表。
- **软换行门禁（`W505`）**：连续普通文本行就是 Markdown 软换行，前一行有无句末标点均不例外。不可分规则写成一个完整段落；独立文字块以空行分段；独立判断用统领项和子列表表达。列表项后的裸文本续行也必须改成真正的子列表或空行后的独立段落。单独一行不带句末标点允许。`> [!IMPORTANT] 标题` 指令行与紧随的第一条 `> 正文` 必须保持物理分行，这是 Callout 语法而非软换行；**且指令行前必须有一个空行**（或块起始、另一引用行、标题、围栏边界），紧跟列表项或段落时它会被解析为续行而无法识别（`E310`）；只有同一 Callout 内连续两行以上普通正文才参与检查。代码围栏、标题、真实列表和表格行不参与此项检查；表格单元格的少量必要分隔仅使用 `<br />`，不能用物理换行拆表格行。
- **样式锚点保全**：`W505`、`W507` 只重组段落、列表和缩进。围栏外的 `**短锚点**{: style="..."}` 与独立 IAL 必须作为不可拆内容完整移入最终句子、父项或子项，不能因消除软换行而删除、降色或改写。围栏内 IAL 由 `W508` 处理时，也必须移到对应渲染块外，而不是直接删除。
- **行内伪编号门禁（`W507`）**：父项只写名称或统领语，子项必须另起行、缩进 4 空格并使用 `1. ...`。`1.`、`1)`、`1、`、`（1）`、`①` 无论前面是冒号、句号、括号还是文字，都不能留在父项行内；它们没有生成 Markdown 子列表。
- **列表项不得以有序列表标记开头（`E311` 硬门禁）**：`- 1. 债务加入生效后，`、`- （1）主体适格。`、`- ① 一部单行刑法。` 这类“项内容紧贴列表标记就是有序列表标记”的写法会被渲染器当作嵌入的有序列表而识别错误。修复：去掉标记只保留内容，或把每个编号分支写成单独缩进的真实 `1. ...` 子行；嵌套子项同样适用。数字后紧跟数字（`1.5 倍`）与 `第X条` 等法定条文编号不触发。
- **代码围栏 IAL 门禁（`W508`）**：围栏只保留标准 Markdown 的题面或源码。`{: ...}`、`custom-qb-*` 和思源颜色样式必须写在围栏外、附着真实渲染块；它们在 `md` 围栏中不会被思源解析，也不能承担题目、答案或解析的边界。
- 一条列表只承担一个主要判断；同一行出现两个转折、两个法律效果或三段以上标点关系时，即使未满 42 字也应拆分。
- 解析达到 160 个可见字符、出现 4 个以上推理句，或出现 3 个以上判断分支、程序节点、主体互动或选项排除时，视为中等及以上复杂度，必须提供一种可插入思源的可视化。达到 320 个可见字符、8 个推理句或 6 个判断分支时视为复杂推理，必须使用 Mermaid。
- **可编辑 Mermaid**：每张图至少包含三个可在同题正文逐字回查的法律节点，并用连线表达条件、先后、归责、例外、涵摄或法律效果。`题干 → 逐项判断 → A 排除/B 当选` 只复述答案，不构成分析，门禁 `E639` 会拒绝。直接输出思源自带 Mermaid.js 可编辑的 `mermaid` 代码块；可以使用 `%%{init}%%`、`classDef`、`style`、`linkStyle`。
- **Mermaid 必须画真判断**：图要连通、复用节点，边标签写明被测关系，或用决策菱形和分支承载推理。孤立的关键词二元组罗列与短关键词裸链都是敷衍格式，门禁 `E901`/`E902` 会拒绝。
  - 坏例（`E901`：四个 `-->` 行各连两个互不共用的节点，只是把“案例→术语”平行摆成一叠，没有共用节点、没有边标签、没有分支）：
    ```mermaid
    flowchart TD
        A["申请信息公开"] --> B["行使权利=守法"]
        C["环保局败诉"] --> D["承担法律责任=强制作用"]
        E["起诉环保局"] --> F["公民监督=社会监督"]
        G["诉权对象特定"] --> H["相对权利"]
    ```
  - 坏例（`E902`：无边标签、无菱形、无分支的短关键词链，等价于一行列表）：
    ```mermaid
    flowchart TD
        A["法律"] --> B["公序良俗"]
        B --> C["权利"]
    ```
  - 好例（共享根节点 + 决策菱形 + 边标签承载判断，一个案例的完整推理链）：
    ```mermaid
    flowchart TD
        A["张某起诉李某"] --> B{"同一法律关系"}
        B -->|"同一借款合同关系"| C["一个诉讼标的"]
        B -->|"不同法律关系"| D["多个诉讼标的"]
    ```
  画不出判断链时直接放列表，不要为凑可视化而伪造 Mermaid。
- **HTML**：Mermaid 难以表达对象、图标、镜像比较或空间布局时，使用 HTML；完整内容由一个外层 `<div>...</div>` 包裹。HTML 负责解构关系，而不是把原解析换成带底色的长文本卡片。
- **静态 SVG/PNG**：需要统一主题、复杂图形或跨端稳定展示时，渲染为资源并以标准图片语法插入思源。替代文本必须包含“可视化”“图解”“流程图”“关系图”“决策图”“时间线”或 `diagram`，使门禁能够区分图示与普通来源图片。Beautiful Mermaid 可用于静态图，但只接受它支持的 Mermaid 子集：`%%{init}%%` 会被丢弃，边标签只能统一设置颜色，不能逐条设置。
- 三种载体都只画主线：文字保持短语化；正文继续保留法源、理由和例外。中等及以上复杂度还必须至少组合 4 类结构载体，其中必须有实质 Callout；Callout 至少承载一项来源支持的法条、条件、例外、程序或法律效果。泛化的“核心考查”“偷换概念”“逐项排除”不计入，并由 `E640/E643` 拒绝。

## 解析结构门禁

答案行及其 `custom-qb-section="solution"` 边界之后的解析不是普通摘抄区。先判断解析中的分支轴：

- 只有一个不可拆的前提 → 行为 → 结论链时，保留为一项短段落。
- 存在多个选项判断、主体地位、程序阶段、例外条件或法律效果时，先写一个统领短句，再把每个分支写成 4 空格缩进的子列表。
- 同一题出现 3 个以上平级解析项目却没有任何子列表、Callout、阶段标题或小表时，视为未完成语义排版；加粗不能替代结构。

每条达到 14 个可见字符的实质推理行至少出现一个短颜色锚点。颜色锚点应落在决定正误的 2-6 字判别词上；不可拆制度名最多 8 字。题面可以无色，但解析必须主动给主体和关键概念建立颜色；解析中再次出现时必须复用。颜色稀疏、整句铺色、长段纯文本、只在结论句着色，或较长解析始终只有粗体和颜色，都应回到“语义色谱/样式语义分工”步骤重新标注。

## 小表格与其他格式

**真实表头先行**：每张新建、重建或拆出的表都先写一行无合并真实列名，第二行紧跟 Markdown 分隔行；`rowspan`、`colspan`、`fn__none` 只能从第三行数据区开始。拆成多张表时，每张表都重复必要表头和分隔行，不能让后续表直接从数据行开始。

**表格尺寸门禁**按“列数 × 数据行数”计算，不计真实表头与 Markdown 分隔行：**严格模式默认最多 `2×2`**（`--strict` 可显式写出、等价默认；只有手动传齐全部宽松参数 `--lenient --max-table-columns N --max-table-rows N` 才启用宽松模式，缺一即拒绝运行）。超过时优先按完整语义类别拆表、改用语义列表或保留来源原表；确有横向比较、数值对齐、映射或合并范围需要时，显式传 `--max-table-columns N --max-table-rows N` 放宽并说明必要性（单表尺寸例外，告警仍按严格处理）。不得为过门禁删减单元格、拆散同一类别或破坏合并关系；来源中原样保留的既有大表不因尺寸门禁强迫改写。表格只承载短小的横向对比、映射或数值关系。若只有“短名称/类别 + 该项完整说明”两列，各行可以独立阅读，且没有第二比较维度、数值对齐、跨行映射或合并范围，它是**单轴名称—说明表**，应改成 `- **名称**` 父项及其完整说明。少量简短编号可以使用 `<br />`。通常达到 4 个独立项目，或达到 3 项且合计约 100 个可见字符时，删除生成表格并转成真实嵌套列表。来源表格可以保持原样，也可以在逐项保全内容后转换。

把生成表格转成列表时**先选主轴**，不默认首列永远是父项。逐格读真实表头、纵向首列和交叉单元格，比较两种展开方向，选择标签更像可独立复习对象、制度、阶段或分类的一轴作为一级列表；另一轴保留原标签并下沉为子列表。

- **横向列作一级列表**：列名是主要对象/概念、纵行是共同比较维度时，以各列名为父项，在父项下按原行名写子项（如列为 A/B、行为要件/后果，写 `- **A** -> 要件、后果` 与 `- **B** -> 要件、后果`）。
- **纵向行作一级列表**：首列各行是主要对象/制度/分类、其余列是它的属性时，以各行项为父项，按原列名写子项（如行为 A/B、列为要件/程序/后果，写 `- **A** -> 要件、程序、后果` 与 `- **B** -> 要件、程序、后果`）。
- **比较轴下沉**：需回答“同一概念下 A 与 B 分别怎样”时，以共同概念/比较维度为父项，把 `A：…`、`B：…` 作为并列子项并保留两端标签与对比色；无需比较时以 A 本身为父项、其要件/程序/期限/例外/后果为子项。
- **保留表格的边界**：读者须同时横向扫视多个对象才能得出结论、数值/期限须对齐、单元格承担多对多映射，或 `rowspan`/`colspan` 表达适用范围时继续保留表格。无合并表格只有在全部表头、行项、非空单元格及其对应关系都能逐项回查时才可转列表。

### 表格绝对保留

原文表格若承担横向对应、数值对齐或合并关系，保持 Markdown 表格形态。若它只是单轴名称—说明结构或容器化的长项目清单，可以原样保留，也可以在完整保留全部文字和对应关系的前提下转成真实列表；不能转换成普通大段或巨型 Callout。

### 枚举项强制软换行

单元格内只有少量简短的 `1、2、3`、`（1）（2）（3）` 或 `①②③` 时，可以用 `<br />` 提升扫描性。达到大型清单阈值后，以列名或类别为父项，将全部内容转为表格外真实子列表。

### 表格单元格排版

表格转出的真实列表必须继续遵守解析区全部门禁：普通行不超过 42 个可见字符，主体与概念主动着色且保持同色，按语义建立子列表，中等及以上复杂度继续满足丰富型样式、结构和可视化要求。不能把转换后的内容保留为无层次大白字，也不能用样式泄露题面答案。

Callout 只包住独立的法条、核心结论、陷阱或禁止后果；不要把整题解析塞进一个 Callout。每个 Callout 指令行前必须有空行（或块起始、另一引用行、标题、围栏边界），否则被解析为续行不会识别（`E310`）。可视化用于确有方向、空间或关系价值的内容，图片、emoji 引述和 InkLoom 动图用于定位或记忆，不得替代原文证据。
