等于号不用\转义!!!

一、处理步骤

1.  标题识别与修复：
    - 必须保留原文标题的文字、编号信息和出现顺序，并以材料实际表达的主从关系输出；不得为了美观重写标题、删去标题信息或重排章节。但标题符号和标题层级是识别结果，不是不可变的事实：存在明确误识别时必须修复。
    - 先通读相邻标题、标题后的正文和同组条目，再决定每个标题标记的结构角色；不要仅因有 `#`、编号、句号或关键词就认定它是标题、列表或同级节点。
    - **编号列表误识别为标题**：若带标题符号的“1.”、“（1）”、“①”等与相邻并列项共同构成规则、要件、情形或步骤，且其后内容是该项的说明，应删除标题符号，保留或规范为有序列表项；把属于该项的后续内容缩进为子项。不得把“一、总则”“（二）管辖”等真正统领下文的章节编号机械降为列表。
    - **习题解析区是强保护区**：从 `###### 习题` 开始，经过题干代码块，到 `**回答与解析：**` 及其后续答案列表，所有数字开头的行都先按题目、答案或解析正文判断。批量处理时，即使输入中已经出现 `#### 1. (1)正确...`、`#### (1) ...`、`##### ① ...`，也只能视为批量识别产生的误标题标记，不能作为标题层级的结构事实；应将其降回 `> 1. ...` 等引用列表或普通正文，并保留法律内容。若其后已有对应的 `1.` 列表，只合并重复的标题外壳，不删除后续解析。
    - **短概念补全数字标题**：脱离习题解析区后，若数字标题本身只有编号，而下一正文行以一个可独立复习的简短法律术语和冒号起笔，应把“编号 + 术语”合成标题，并让正文从冒号后的定义开始。这样大纲同时保留顺序和语义；术语已经进入标题后，不在正文重复。例：

      ```md
      ### 1. 六赃

      六种非法获取公私财物的犯罪，具体包括以下罪名：
      ```

      原来的 `### 1.` 与 `六赃：六种非法获取……` 不得原样保留。该规则只补全短概念标题；习题仍以数字计数，题干留在题目代码块或正文中，不把完整题干塞入大纲。
    - **数字开头何时才可能是标题**：必须同时满足脱离题目解析区、具有独立概括性的标题短语、并有相邻多个独立同级分支或明确父标题证据。单独一条数字答案、答案选项、解析序号或“正确/错误”句，永远不是标题。用户明确允许删除不标准标题时，按上述语义证据删除误识别的标题标记，不为保留原标记而制造层级。
    - **断开的标题**：相邻标题之间没有独立正文，后一个片段只是前一个片段的定语、宾语、限定、范围或补足时，合并为一个标题，保留片段原有顺序和全部文字。合并后使用前一片段所属的标题层级；有独立定义、规则、列表、表格、图片或 Callout 间隔时，不得合并。
    - **子标题误识别为同级标题**：当后一个标题只展开、限定或分解紧邻前一标题，且脱离前一标题不构成可独立复习的范围时，降为前一标题的子标题，并承接最近的语义父节点。只有各标题各自统领独立规则、对象、范围或法律效果时，才保留同级。
    - 遇到证据不足的边界情形，保留来源层级并标记为待复核；不得凭相同关键词、相邻位置或编号形式臆断父子关系。
    - 修复完成后检查：每个标题都应能概括其直属内容；列表项不得以标题形式残留；合并后的标题不得遗漏任一来源片段；同级标题应分别具有独立的复习范围。

### 超大表格的补充摘要

- **先判断是不是表格**：只有存在真实横向比较、映射、数值/期限对齐或合并范围时才使用表格。若结构只有“短名称/类别 + 该项完整说明”两列，各行可独立阅读，且没有第二比较维度，则它是列表型信息，不是比较表；删除生成表格，改为 `- **名称**` 父项及其规则正文。规则内部只有出现可独立复习的条件、程序、例外或法律效果分支时才继续拆子列表，不能按标点机械切碎。
- **名称—说明列表示例**：`本院启动`、`上级法院启动` 分别统领各自完整启动规则时，应写成两个加粗父项；不要为了“启动方式 / 具体规定”这两个表头制造两列表格。反之，若还要同时比较启动主体、审级范围、处理方式、期限等共同字段，则保留多列对照表。
- **表格必须保留为表格并先整理好**。背诵卷、至少约 8 个数据行、至少 4 个信息列，或单元格已堆叠多个独立规则而使横向阅读明显困难时，可在该表格结束后新建一份等义 Markdown 摘要；这是补充复习视图，绝不替换、删减或遗漏原表信息。
- **允许按完整类别组拆分超大表格**：当同一张表连续介绍两个或以上各自独立的类别，并且每个类别均包含一组相同或可对应的事项时，可按类别边界拆成多个相邻小表。例如“诉前保全”“诉讼中的保全”“执行前的保全”分别成为一张表；拆分后的表仍按原顺序排列，并保留各类别下的全部事项、规则、条件、期间、主体和法律效果。
- **只按语义类别边界拆分**，不得按固定行数或视觉长度随意切表。原表中由 `rowspan`、`colspan`、首列类别名、分组标题或 HTML `<table>` 的行组表达的类别，拆分后应成为每张小表紧邻的类别标签或已有的子标题；共同表头需要在每张小表重复，合并单元格表达的适用范围和对应关系必须在对应小表中完整展开。
- **拆表后的标题骨架**：拆分前先确定父标题和每个独立类别的子标题。每张拆出的表都必须紧邻一个能概括该完整规则组的合法 Markdown 标题，标题层级承接最近的父标题；不得只输出“诉前保全”这类裸文本后直接跟表格，也不得把首个单元格机械当作标题。若来源只有类别标签，应将其规范为合适层级的标题，例如 `#### 诉前保全的适用情形`，同时在表格中保留该类别及其全部法律信息。
- **标题与表格的一一对应**：标题应覆盖该表的全部行、条件、主体和法律效果；同一类别的多行不得各自生成标题，独立类别不得共用一个含混标题。若无法为拆出的表确定独立、准确的标题，应先保留原表或标记待复核，不得用裸文本占位。
- **按信息关系选择补充格式**：按“项目/要件/步骤/情形 -> 规则或后果”逐项展开更清楚的，使用有序或嵌套列表；一组独立的例外、限制、风险或法条原文适合单独提醒的，使用相应类型的 Callout。每个摘要分组保留原列名作为提示词，按原表行序呈现全部规则、限定和法律效果。
- **主动做语义拆分**：不得把长单元格原样复制成表后的一大段文字。先在原表中用短提示词和 `<br />` 分开可独立复习的分支；再在补充摘要中以“原行项目”为父项，将各分支写成嵌套子列表。各片段只有在分别具有适用范围、判断对象、分支结论或法律效果时才拆开；同一规则链中的前提、程序和后果仍保留在同一项。
- **表格拆分审计**：只有内容短、只表达一个规则、没有并列措施/条件/例外/后果的单元格可保持一行。其余单元格一律先做语义分段：措施、适用条件、程序、期间、例外、登记或对抗效果、法律后果等分别加短提示词，并以 `<br />` 分开；不得因为原文没有编号就保留一大段。
- 各列需要横向交叉比较、同一行必须与多个列同时对应、单元格合并本身表达范围或关系、数值/期限需要并排比较时，表格尤其不能省略；可在表后补充列表，帮助背诵，但不得以摘要取代对应关系。
- **禁止只因表格很长就概括**：补充文本不得遗漏表头、行项目、例外、条件、主体、期间、数字、法条依据或结论；不得把多列对应关系压缩成无来源的概括句。编写前逐行建立“原列名 + 原行项目 + 原内容”的对应，完成后逐项回查。
- **Callout 只承载有明确属性的一组规则**，不得把整张大表机械包进一个巨型 Callout；同组中仍使用列表展示多个独立项。普通规则优先使用列表，法条原文使用 `NOTE`，例外或易错限制使用 `CAUTION`，严重禁止或无效后果使用 `WARNING`。
- 补充摘要的目标是降低背诵时的扫描负担，而不是改写法律含义；原表与摘要应能逐项互相对应。
    - 【图片绝对保留】：遇到图片 Markdown 链接，必须原封不动地保留在对应知识点处，绝不能删除、遗漏或篡改！输出时直接保留其原始图片语法，不额外包裹行内代码反引号。
    - 🚨 **【表格绝对保留】**：表格形态、全部单元格信息和对应关系必须保留；这不要求超大表格永远维持为一个单体表，可按完整类别组拆成多个小表。
      - **思源笔记表格语法**：用户粘贴的内容来自思源笔记，表格使用**扩展 Markdown 语法**（不是 HTML `<table>` 标签），必须原样保留以下语法：
        - 合并列：`{: colspan='n'}` — 如 `| {: colspan='2'}合并单元格 |`
        - 合并行：`{: rowspan='n'}` — 如 `| {: rowspan='2'}合并单元格 |`
      - 被合并的空单元格：`{: class='fn__none'}` — 如 `| {: class='fn__none'} |`
      - 单元格内软换行：使用 `<br />` 标签；不要用物理换行拆断 Markdown 表格行。
      - **合并网格先行**：编辑、重建或拆分合并表前，先按表头的物理列数画出逻辑网格。每个 `colspan='n'` 在同一行必须占用连续 `n-1` 个 `fn__none`；每个 `rowspan='n'` 在后续连续 `n-1` 行的同列必须是 `fn__none`；二维合并则同时满足两项。反过来，每个 `fn__none` 都必须能追溯到左侧 `colspan` 或上方 `rowspan`，不得孤立出现。
      - **表头与数据分离**：新建或重建表格时，先写一行不合并的真实列名，再写 Markdown 分隔行；不要把首个数据行放在分隔行之前，否则它会被渲染为表头。保留原始材料中已存在的合并表头，除非用户授权结构性重建。
      - **最小属性**：只在跨度大于 1 时写 `colspan` 或 `rowspan`；`colspan='1'`、`rowspan='1'` 不表达合并关系，必须删除。
      - 除按“超大表格类别拆分”完整展开分组关系外，**禁止拆散合并单元格**，禁止删除 `colspan`、`rowspan`、`fn__none` 等属性。
      - 对符合“超大表格的补充摘要”条件的表格，可在原表或按类别拆分后的小表下方新增列表或多个小型 Callout；表头、行项目、合并单元格表达的范围和法律对应关系仍必须完整保留。
      - **超大表格类别拆分**：只有存在两个或以上完整类别组时，才可将一张表拆为多张表；每张表必须紧邻其类别标签，重复必要表头，并保留该类别全部行。不得把同一类别的行拆散到不同表，不得用列表或 Callout 替代拆出的表格。
      - **单元格不承载大型列表**：真正的对比单元格可以用 `<br />` 分隔少量简短编号。通常达到 4 个独立项目，或达到 3 项且合计约 100 个可见字符时，将列名/类别写成父项，把全部内容转换为表格外的真实 Markdown 子列表。
      - **表格处置**：Agent 新建或重排的列表型表格直接删除并改用真实列表；来源中已有的表格可以原样保留，再在表外增加等义列表。不得一边保留表格，一边继续向其单元格添加编号项目。
      - **单轴名称—说明表改列表**：首列只是短名称/类别，次列只是该项完整规则，各行无需对齐其他共同字段时，来源表也可以在逐项保全内容后直接改成加粗父项列表。不要保留“类型 / 具体规定”之类并不承担比较任务的空泛表头。只要存在第二比较轴、数值/期限对齐、跨行映射或合并范围，就继续使用表格。
      - **转换列表继续过门禁**：表格转出的每个父项和子项仍执行普通 MarkNote 的 42 字行长、主动语义颜色、主体同色、样式密度、嵌套层级和丰富型规则。转换不是降低排版标准的例外。
      - **真正表格的范围**：只有横向对比、映射、数值对齐或合并关系需要表格。短单元格可以使用 `<br />` 做普通软换行或分隔少量编号，但不能借此容纳大型项目清单。

2.  内容整理与高亮：
    - **习题处理模板**：
      > ###### 习题
      >
      > ```md
      > [考查类型] 题干内容...
      > ```
      >
      > **回答与解析：**
      >
      > 1. ==答案==。解析内容...
    - ⚠️ **代码块规则**：所有代码块必须在 `> 引述块` 内，每行以 `> ` 开头，仅使用 ` ```md ` 围栏。
    - **习题标题只写一次**：同一个连续引述习题组只在第一道题前写一次 `> ###### 习题`。后续短题直接使用各自的 `> ```md` 代码块，不重复“习题”，也不另造“习题1”“习题2”“习题3”；题块内的来源题号已经承担定位功能。
    - **习题代码块编号不可变**：可以把多个短题拆成多个 `> ```md` 题块，但题块内部的原题号、小问号、标点形式和先后顺序必须原样保留。来源中的 `37.`、`42.` 拆块后仍是 `37.`、`42.`，不得按新块序改成 `1.`、`2.`。这条规则只保护习题代码块中的来源编号，不影响代码块外普通知识列表的 Markdown 标准化。
    - 【法条完整保留】：文中出现的法条原文，必须使用 `> [!NOTE]标题` 提示块完整包裹保留。不能随意删减法条原话，并需在法条的核心构成要件和法律后果处，按规范设置"隐形提示+高亮"。
    - 不是考点的地方简单整理，但不能彻底跳过。
    - 保持单行的简短，多用样式降低阅读疲劳。不要滥用分隔线。
    - 积极添加口诀、缩写等附注辅助记忆（如公检法缩写或谐音），直接嵌入对应知识点，并优先使用 `> [!TIP]标题` 格式。
    - 如果单独发的图片 那就利用多模态识别内容和逻辑关系 转为md 不要额外添加内容。

3.  闪卡化表述与隐形提示法（核心要求）：
    - **隐形提示法**：将提示词（如属性、原因、性质、后果等）自然融入主干句子并**加粗**，去掉括号。
      - 示例：教育心理学的**学科性质**是==心理科学==与==教育科学==的==交叉==产物。
    - **高亮语法**：用 `==高亮==` 标记答案（绝对不能输出为隐藏带转义的 `\=`）。
    - **高亮原则**：
      - ❌ 禁止高亮整行或整段话！要保留前后的提示和连接词。
      - ✅ 控制每个高亮的长度（最小化原则，禁止一个高亮超过6个字）。
      - ✅ 多个关键词必须用多个独立高亮，中间用标点或文字隔开。
      - 错误示范：`==民事主体====三元论==`
      - 正确示范：我国采用==民事主体==的==三元论==。
4.  自动拆分复杂知识点（重要！）：
    - 如果一个长句包含多个维度的考点，必须使用换行将其垂直拆分为列表，利用列表的递进表示逻辑关系，降低单张闪卡的认知负荷，保证边界清楚。
    - **【绝对尊重原文与缩进规范】**：
      - **物理拆分**：必须严格使用原文的表述和词汇进行断句切分！严禁为了凑格式而自行添加、脑补、概括或过度改写。只做"物理拆分"和"提取加粗提示词"，不做"化学改变"。
      - **强制Markdown列表语法**：必须确保拆分后的每一项都被识别为标准的Markdown列表。
        - 标准有序列表（如 `1.` `2.`）直接使用。
        - 原文中的 `(1)`、`①`、`（一）` 等编号，应转换为标准有序列表 `1.` `2.`，删除原编号，避免数字重复。
        - 例如原文 `(1) 考点A` 应转为 `1. 考点A`，而非 `- (1) 考点A`。该规则适用于习题代码块之外的知识整理；不得据此修改 `> ```md` 题块内的来源题号。
    - **缩进与子列表规则**：
      - 🎯 **积极使用缩进**：缩进是展示层级关系的最佳方式！遇到包含子要点、递进关系、条件分支的内容时，**必须主动使用缩进**创建子列表。
      - 缩进能显著提升可读性，让逻辑关系一目了然，降低认知负荷。
      - 使用标准 Markdown 缩进格式，子列表通过缩进实现层级递进（通常缩进2-4个空格）。
      - 鼓励多层缩进：当知识点存在"条件→结果"、"情形→后果"、"要件→要素"等递进关系时，应积极使用缩进。
    - **语义断行与子列表判断（必须执行）**：
      - **按语义原子判断，不按标签或标点机械触发**：期限、条件、情形、程序等词只能提示一个范围，不能单独决定拆分；句号、分号、顿号和“或者”也不是拆分开关。只有当片段各自具有独立的适用范围、判断对象、分支结论或法律效果，能够分别复习和分别回答时，才拆成同级有序子列表。
      - **同一规则链保持一体**：前提、行为要求、程序安排和结论如果共同完成一个不可分割的法律判断，就保留在同一项中；不要因为出现标签或多个分句，就把“条件→处理→后果”机械拆开。
      - **正例**：国内诉讼与境内无住所分别对应不同公告送达期限和效果，属于两个独立分支，应拆为子列表。**反例**：需要当事人申请，法院不能主动依职权顺延，共同说明同一程序的权力配置，应保留为一项。
    - **❌ 错误示范（数字重复）**：
      - (1) 考点A... （解析：保留了原编号 `(1)`，与列表符号重复）
    - **✅ 正确示范**：
      1. **爽约**。在爽约的情形下，行为人双方的法律责任是均==无需承担==赔偿责任。
      2. **极力或恶意劝酒**。在请客吃饭过程中，若主观状态是==极力==或==恶意劝酒==：
         1. 应认定其在归责要件上具有==过错==，
         2. 其行为性质构成==一般侵权==，
         > [!NOTE] 容器内缩进示范
         >
         > 1. 容器内第一级列表
         >    1. 容器内第二级列表
      3. **习题示例**：
         > ###### 试一试
         >
         > ```md
         > [综合应用] 房屋A登记在甲名下...问题：(1)丙能否善意取得房屋A的所有权？(2)甲对乙是否构成表见代理？
         > ```
         >
         > **回答与解析：**
         >
         > 1. ==不能==。善意取得中的"善意"是相信==占有==或==登记==...
         > 2. ==否==。甲以甲、乙二人名义卖房对乙构成==无权代理==...

5.  **对比辨析处理**：
    - 原文中涉及概念对比、易混淆辨析的内容，优先使用**表格**呈现。
    - 表格结构：左侧为对比维度，右侧为不同概念的具体内容。
    - 示例：
      | 对比维度 | 盗窃罪 | 抢夺罪 |
      | :--- | :--- | :--- |
      | 行为方式 | ==秘密窃取== | ==公然夺取== |
      | 暴力程度 | ==无暴力== | ==对物暴力== |
    - 若原文为段落式对比，可转换为表格，但需**忠于原文表述**，不得自行概括。
    - 🎨 **HTML可视化图表的使用**：
      - 当知识点涉及**流程、步骤、条件判断、逻辑关系、时间线**时，鼓励使用 HTML 生成美观的可视化图表。
      - **Mermaid 的语义触发**：当材料包含程序顺序、时间线、判断分支、主体关系或对照路径时，必须使用 Mermaid 表达该关系；图表类型和节点名称服从真实内容，不为套模板而添加无意义图表。简单的单规则定义不强制使用 Mermaid。
      - **Mermaid 的视觉样式**：不要交付默认蓝灰色的裸图。触发 Mermaid 后必须先调用已安装的 `beautiful-mermaid` 技能，按其工作流渲染 SVG/PNG 预览，并检查主题、语义配色、节点样式、标签和方向；主体、法院/机关、规则、成立结果和危险/无效结果应有稳定且可区分的视觉层级。支持图片资源时引用渲染结果，需要可编辑性时保留源码；两者都不能省略渲染检查。节点标签保持短语化，含括号或标点时使用引号，避免交叉线、过长节点和无意义装饰。
      - 常用场景：法律程序流程、构成要件的判断流程、时间线、因果关系、对比框架等。
      - **使用原则**：HTML图表应作为辅助总结工具，不能替代文字考点，应在文字说明后添加"**可视化总结**："并附上图表。
      - **HTML图表优势**：
        - 支持丰富的颜色、边框、阴影等样式
        - 可嵌入思源笔记颜色语法，与文档风格统一
        - 布局灵活，可制作流程图、时间线、对比卡片等
      - **示例场景**：
        - 流程图：用 `<div>` + CSS 制作带箭头的流程步骤
        - 时间线：用左边框 + 时间节点标记
        - 对比卡片：用并排的 `<div>` 展示不同概念
        - 构成要件图：用嵌套的 `<div>` 展示层级关系

6.  Callout 提示块的高阶使用（精准分层，切忌滥用！）：
    - 仅在合适或必要的地方，将具有特定属性的原文转换为标准 Callout 提示块。普通陈述型考点不要放进提示块中。
    - 🚨 **不得机械将原文表格转为 Callout！** 对比关系、横向对应关系或合并单元格承载关系的表格必须保留，仅对表格单元格内的关键内容做加粗/高亮/染色处理。仅在“超大表格的补充摘要”明确适用、且每个分组保留原列名和全部规则时，才可在表格后用多个小型 Callout 承载适合提醒的独立规则；Callout 不能替代需横向比较的表格。
    - 字母必须全大写，块内仍需执行"隐形提示+高亮"原则，可嵌套列表。
    - **⚠️ Callout 内部格式规则（重要！）**：
      - Callout 提示块内部的**每一行都必须以 `> ` 开头**，包括空行、列表、子列表等所有内容。
      - ❌ 错误示范（列表行缺少 `> `）：
        ```
        > [!CAUTION] 注意事项
        > 这是第一行内容
        1. 这是列表项（错误：缺少 `> `）
        > 这是后续内容
        ```
      - ✅ 正确示范（所有行都有 `> `）：
        ```
        > [!CAUTION] 注意事项
        > 
        > 这是第一行内容
        > 
        > 1. 这是列表项（正确：有 `> `）
        >    - 这是子列表（正确：`> ` 后缩进）
        > 
        > 这是后续内容
        ```
      - 子列表的缩进是在 `> ` 之后进行的，格式为 `>    - ` 或 `>    1. `。
    - 使用规范与触发场景：
      - `> [!TIP]标题` （贴士/技巧）：仅用于记忆口诀、速算技巧、学习捷径。
      - `> [!NOTE]标题` （备注/引述）：用于法条原文的完整保留、不影响主干的背景延伸、名词引申解释。
      - `> [!IMPORTANT]标题` （重要/核心）：仅用于极度重要的核心结论、必背金标准、统领全局的核心原则。
      - `> [!CAUTION]标题` （注意/误区）：仅用于考点中的常见陷阱、易错点、例外条件、特殊限制。
      - `> [!WARNING]标题` （警告/高危）：仅用于法律上的严格禁止行为、会导致无效或严重违法后果的操作。

7.  FSRS推荐的闪卡特性遵守：
    - 一张卡片只对应一个核心知识点/事实/术语；问题与答案之间边界清楚，不容易混淆。
    - 文字表达必须简短、口语化、聚焦要点。非考点内容用简明语句精炼概括，冗余或背景性叙述控制在1~2行以内，案例可以简化保留。

8.  结构化与样式要求：
    - 整体以普通markdown输出，不得用代码块包裹全体或大段内容。
    - 充分利用 markdown 的加粗、_斜体_、`==高亮==`、`~~删除线~~`、行级代码、下划线、分隔线、列表、Callout、表格和 Mermaid 等标记丰富层次；普通正文行最多 42 个可见字符，超过时按语义拆成父项与子列表。
    - 每两段间至少两个换行分隔。合理穿插Emoji点缀，提升辨识度。
    - 闪卡内容紧贴考点原文，仅在原文句中用"隐形提示词 + ==高亮内容=="替换，不单独列出Q/A卡片模板。
    - 📊 **总结性内容的可视化**：
      - 当一个章节或知识点结束后，鼓励添加**总结性表格**或**Mermaid图表**。
      - 表格适用于：概念对比、要件列举、情形汇总、关键词提取。
      - Mermaid适用于：流程展示、逻辑关系、时间线、决策树、主体关系和正反路径比较；中等及以上复杂度的材料，只要存在上述关系就必须使用 Mermaid。
      - 示例：在整理完"善意取得的构成要件"后，可添加：
        | 构成要件 | 具体内容 |
        | :--- | :--- |
        | 善意 | ==不知情== |
        | 合理价格 | ==支付对价== |
        | 已交付 | ==完成交付== |

9.  🎨 思源笔记行内文本颜色语法 (Siyuan Notes Inline Color Syntax)：
    - **基本语法格式**：
      ```markdown
      **文本内容**{: style="color: var(--b3-font-color数字); background-color: var(--b3-font-background数字);"}
      ```
      也可以只使用背景色：`**诉讼中**{: style="background-color: var(--b3-font-background11);"}`。无论使用前景色、背景色还是二者组合，IAL 都必须紧跟在 `**加粗文本**` 后；`文本{: style="..."}` 不生效且会触发门禁。
    - **🎯 颜色不是可选装饰，而是信息结构的一部分**：颜色能形成视觉锚点、区分关系并降低检索成本。除非原文确实没有可区分的主体、概念、状态或结果，否则不要只使用黑白文字、加粗和高亮。
    - **先做颜色计划，再输出正文**：每个章节、案例或表格先识别可复用的 3-5 个语义角色，并在该范围内固定映射；多方主体或复杂关系可扩展至 5-7 个颜色。相同主体、概念和状态在同一篇笔记中必须保持同色，不能随段落随机换色。
      - **主体与关系**：为反复出现的当事人、机构、客体或法律关系分配可清晰区分的颜色，例如甲/债权人用 10，乙/债务人用 8，第三人用 11。
      - **规则与状态**：定义、要件、法条术语优先用 10；成立、有效、应当或正确结论优先用 8；例外、注意和限制优先用 5 或 12；禁止、无效和严重风险优先用 13。
      - **对比与表格**：同一对相反概念必须使用稳定的对比色，例如有效/无效用 8/13。真正用于横向对比的短表格保留原结构和一致颜色锚点；若单元格达到大型清单阈值，则转成表外真实列表，并在列表中继续复用相同颜色。
    - **主动覆盖规则**：遇到以下内容必须主动添加颜色，而不是等用户指定：
      1. 文中重复出现的同一概念、主体、法律关系或法条要件。
      2. 需要并列辨认的主体、权利义务、条件分支、时间节点或因果链。
      3. 有成立/不成立、有效/无效、原则/例外、允许/禁止等可比较状态的内容。
      4. 一个独立知识块中存在至少两个可区分的语义角色时；每个角色至少在首次出现和后续关键出现处着色。
    - **密度与边界**：颜色服务于扫描，不是给整段上色。每个独立知识块优先放置 2-4 个短的颜色锚点；不要给整句、整行、连接词、标点或每个普通名词染色。颜色与 `==高亮==` 可以配合，但同一个短语只承担一种主要视觉强调，避免视觉噪声。中等及以上复杂度时，至少使用 4 类辅助样式、4 类结构载体和 3 个短背景色锚点；由内容决定具体组合，不固定生成同一组小节。
    - **13种可用颜色变量对照表与语义化使用建议**：
      | 颜色编号 | 浅色主题效果 | 深色主题效果 | **推荐语义化使用场景** |
      | :--- | :--- | :--- | :--- |
      | 2 | 深灰色文字，浅灰色背景 | 中灰色文字，半透明深灰背景 | 次要信息、注释、补充说明 |
      | 3 | 深棕色文字，浅灰棕色背景 | 浅棕色文字，半透明深棕背景 | 自然、历史、地理相关内容，或作为一种区分色 |
      | 4 | 深橙棕色文字，米色背景 | 浅橙棕色文字，半透明深橙棕背景 | 暖色调强调，引人注意但不过于强烈 |
      | 5 | 橙色文字，浅橙色背景 | 明橙色文字，半透明深橙背景 | **一般警告**、**提醒**、待办事项的"进行中"状态 |
      | 6 | 深黄色文字，浅黄橙色背景 | 明黄色文字，半透明深黄背景 | **重要提示**、**亮点**、需要特别关注的内容 |
      | 7 | 橄榄黄色文字，浅黄色背景 | 橄榄黄色文字，半透明深橄榄背景 | 标记、高亮文本（类似荧光笔效果） |
      | 8 | 深青绿色文字，浅绿色背景 | 明绿色文字，半透明深绿背景 | **成功状态**、**正确示例**、已完成事项、推荐做法 |
      | 9 | 青绿色文字，浅青绿色背景 | 明青绿色文字，半透明深青绿背景 | 清新、活力相关内容，或作为另一种区分色 |
      | 10 | 深蓝色文字，浅蓝色背景 | 明蓝色文字，半透明深蓝背景 | **信息性文本**、**定义**、链接（若不使用默认链接色）、术语解释 |
      | 11 | 深紫红色文字，浅紫色背景 | 明紫色文字，半透明深紫背景 | 特殊标记、独特概念、创意性内容 |
      | 12 | 深红色文字，浅粉色背景 | 橙红色文字，半透明深橙红背景 | **较强调整**、**次级警告**、截止日期临近 |
      | 13 | 鲜红色文字，浅红色背景 | 明红色文字，半透明深红背景 | **严重错误**、**危险操作**、**禁止事项**、**最终截止日期** |
    - **使用注意事项**：
      1. **数字范围**：颜色编号必须是 **2-13** 之间的整数。
      2. **语法完整性**：确保花括号 `{}`、冒号 `:`、分号 `;` 等符号完整且使用正确。文字部分不能与`行级代码`共用，只能与**加粗**结构共用。
      3. **自动染色**：可以对重复出现的人事物、概念等**加粗并**染为同色。相邻颜色间差别要大，最好冷暖搭配。务必牢记：**只要使用染色代码，该文本本身必须先用 `**` 加粗！**
      4. **语义化使用**：强烈建议根据内容的性质和上述表格中的"推荐语义化使用场景"来选择颜色，以增强信息的可读性和表达力。
      5. 可以混搭背景与颜色，也可以独立使用，选择最合适语义的。
      6. **🚨 致命红线：颜色的挂载规则 🚨**
         **大模型在这一步非常容易犯错！** 只要输出思源笔记的颜色样式 `{: style="..."}`，**必须且只能紧跟在加粗 `**文本**` 之后！**绝不能因为频繁使用而偷懒省略加粗符号！**
         - ❌ **绝对禁止（附着在纯文本后面会失效）**：`债权人{: style="color: var(--b3-font-color10);"}`
         - ✅ **强制唯一样板（必须先加粗该词语）**：`**债权人**{: style="color: var(--b3-font-color10);"}`
      7. **💡 颜色使用最佳实践**：
         - **主体区分**：`**甲**{: style="color: var(--b3-font-color10);"}`、`**乙**{: style="color: var(--b3-font-color8);"}`、`**丙**{: style="color: var(--b3-font-color11);"}`
         - **结果对比**：`**有效**{: style="color: var(--b3-font-color8);"}` vs `**无效**{: style="color: var(--b3-font-color13);"}`
         - **概念标记**：`**善意取得**{: style="color: var(--b3-font-color10);"}`（定义性概念用蓝色）

    三、任务流程

- 严格按章节、小节顺序整理输出；每个知识点都进行“隐形提示+高亮”标注；复杂句必须换行拆分；精准判断是否需要使用 Callout 提示块；遇到图片绝对保留；每个页面内容之间用空行分隔。
- 保证内容既便于直接粘贴到思源/Obsidian等MD工具中，又能直接用作间隔重复型闪卡基础。

四、特别注意

- 精确理解、拆解与合并知识点，避免内容重复、冗余。
- **严禁过度发挥**：列表拆分等格式调整必须建立在**完全忠于原文核心表述**的基础上，绝不能因为要排版就乱加词汇。
- **超大表格拆分与补充受限**：原文表格必须以完整表格信息保留；仅对存在完整类别组的超大表格，才可按类别拆为多个小表。符合“超大表格的补充摘要”的表格，可在其下方追加等义列表或多个小型 Callout。横向比较、合并单元格关系、数值对照等表格尤其不得被摘要替代。
- **保留思源表格语法**：未拆分的表格中，`{: colspan='n'}`、`{: rowspan='n'}`、`{: class='fn__none'}` 等属性必须原样保留。按完整类别拆表时，可将这些合并关系展开为每张小表的类别标签、重复表头和完整行组，禁止丢失其表达的范围或对应关系。
- 如有原文中未明确为考点的内容，可精练一行概括，不加高亮。

五、❌ 常见错误汇总（输出前必查）

| 错误类型 | ❌ 错误示范 | ✅ 正确做法 |
| :--- | :--- | :--- |
| 高亮整段 | `==整段话都高亮了==` | 只高亮关键词 `==关键词==` |
