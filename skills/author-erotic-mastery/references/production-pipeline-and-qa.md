# 小说流水线生产与多重质量门禁 (Production Pipeline & Quality Gates)

> 本文件是 `author-erotic-mastery` 技能的顶级工程协调参考文件。当执行**章节写作、草稿交付、版本修订或长篇小说工程推进**时必须无条件常驻激活。

---

## 一、核心哲学：从“单次生成”到“生产流水线”

模型写作最大的顽疾是 **One-shot Generation（写完即自认为交工）**。如果让写作者（Writer）身兼审稿人（Reviewer），模型必然会默认自己的初稿完全合理。

**铁律：Writer 永远没有权限直接宣布 DONE。**
章节产出必须通过 **七阶段流水线（Production Pipeline）**，且只有通过最终独立的 **Quality Gate（审查门禁）**，才能将草稿归档为正式正文并更新状态。

```text
       ┌───────────────┐
       │ ① 前期准备    │ (World/Canon + Style Profile 锚定)
       └───────┬───────┘
               ▼
       ┌───────────────┐
       │ ② 剧情设计    │ (自由发散 + 有机推移三阶段)
       └───────┬───────┘
               ▼
       ┌───────────────┐
       │ ③ 写前检查    │ (核对上一章末尾、当前身体/情感状态、未收线索)
       └───────┬───────┘
               ▼
       ┌───────────────┐
       │ ④ 正文写作    │ (Writer 输出 draft.md，严禁单发收工)
       └───────┬───────┘
               ▼
       ┌───────────────┐
       │ ⑤ 独立复查    │ ──[审查发现问题]──┐
       │ (Review Gate) │                   ▼
       └───────┬───────┘           ┌───────────────┐
               │ [PASS]            │ ⑥ 针对性修订  │ (Editor 仅修问题，不推倒重来)
               │                   └───────┬───────┘
               │                           │ (重新送审)
               │ ◄─────────────────────────┘
               ▼
       ┌───────────────┐
       │ ⑦ 入库与更新  │ (草稿转正为正式章节，同步 state.md 与 scene-log.md)
       └───────────────┘
```

## 二、七阶段流水线执行细则

### 阶段 ①：前期准备 (Pre-Production)
- 锁定世界观基线与人物设定卡（禁止凭空捏造与设定冲突）；
- 挂载 `references/author-style-distiller.md`，确立本书的 **Style Profile（文风声线）**。

### 阶段 ②：剧情设计 (Story Architecture)
- 调用 `references/plot-expansion-engine.md`；
- 拒绝机械因果公式，以松弛生活化漫步展开三阶段，确保自然容纳 5000+ 字的真实心理与情境厚度。

### 阶段 ③：写前状态检查 (Pre-write Gate)
动笔前必须强制检查上文连续性：
- **物理接口**：主角和女主上一章结束时在哪个房间？身上穿什么？外面的时间是上午还是深夜？
- **生理与情感状态**：上一章是否有未愈的疲惫、是否有刚发生过的争执、好感度处于哪一层？

### 阶段 ④：正文起草 (Drafting)
- 调用核心规约（踩脚带成箍、蜷缩足穴、开宫六步法、腹凸按压、多女推车加压）；
- 产出内容标记为 **`[DRAFT 草稿]`**，禁止对用户声称“已完结写好”。

### 阶段 ⑤：独立对抗式复查 (Independent Review Gate)
由系统模拟/调用独立的 **Reviewer 角色**（如已安装的 `story-review` 机制），只挑毛病、不夸赞、不写正文：
- **P0 连贯性硬伤 (Continuity Check)**：时间、地点、衣物、称呼、已死/不在场人物是否穿帮？
- **P1 核心 XP 与修辞红线 (XP & Diction Check)**：是否违规出现了“袜筒/布条/布带”？是否有生硬中二独白？开宫后是否误写成了松弛漏精（必须是 Lock-in 紧锁）？
- **P2 文风与 AI 味扫描 (Deslop Check)**：是否存在排比对仗、假深刻单行总结？调用 `story-deslop` 扫描。

### 阶段 ⑥：针对性定向修订 (Targeted Revision)
- **精准动刀**：Editor 针对第 ⑤ 步列出的问题清单逐条修复，禁止无脑整段重写导致丢失细节。

### 阶段 ⑦：再审通过与状态入库 (Final Pass & State Commit)
- 当复查报告为 `PASS` 时：
  - 正式将文稿写入章节文件（如 `scenes/01-xxx.md`）；
  - 同步更新连续性状态：`continuity/state.md`（更新角色生理/心理状态）与 `continuity/scene-log.md`（记录本章推进事实）。
- 此时流水线才真正完成闭环！

## 三、三级质量保障节奏 (Multi-Tier QA)

不要每写一章都做耗费巨大算力的全书体检，执行三级分层：
1. **每章级 (Per-Chapter QA)**：连续性常识 ＋ 踩脚袜修辞黑名单 ＋ story-deslop 网文去 AI 味。
2. **每 3~5 章批次级 (Batch QA)**：检查多女主关系平衡度、踩脚袜玩法是否出现重复单调、伏笔回收度。
3. **分卷/篇章终结级 (Volume QA)**：主线大事件闭环、情感归属与长期生理烙印（如受孕与身心彻底臣服）。
