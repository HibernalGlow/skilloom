# 真金题与闪卡的嵌入

真金题 md 结构：`# 专题标题` → `## 📌 考点必背`（若干 `### N. 小节`）→ 逐题（`##### 题号` + 题干 + `###### 答案与解析`）。闪卡 md 是卡片堆（kramdown IAL `custom-dm-card-id`）。

## 一、真金题

### 考点必背区的锚定

1. 场景 title 与小节标题**语义匹配**（"哪些程序可以调解"→"### 1. 调解的范围"），Edit 插在小节标题行后，空一行
2. 同一小节最多 2 张，溢出上移 `## 📌 考点必背` 标题后按清单顺序排
3. 文件无 `###` 小节：全部场景按清单顺序落 `## 📌 考点必背` 标题后（或文件首个主标题后）
4. 文件 ↔ 动画映射按**专题标题关键词**——序号在真金题与讲义间错位（民诉真金题23督促↔讲义22；刑法动画N↔真金题N-1）

### 题目解析区 —— 防剧透 + 解析区内位置（用户 2026-09-01 双重纠正）

**防剧透铁律**：图只能在解析区内，题干前/题号后/考点节标题后绝对禁止（违规=剧透）。

**解析区内位置（2026-09-01 纠正）**：图**不能插在 `###### 答案与解析` 标题行后**——渲染异常（图片占满渲染区遮挡内容，截图实测）。正确位置按优先级：
1. **`###### 逐项回查/逐项判断/逐项解析` 标题行之前**（规则拆解/判断链之后）——通用考点图默认位
2. 仅针对某一个选项的图 → 插进该选项的解析条目内
3. 无"逐项*"小节的解析 → 插在解析区末尾（下一题题号之前）

批量归位配方（历史事故：726 图曾插解析标题行后，2026-09-01 已全量移至逐项前）：扫描 `###### 答案与解析` 后紧邻图组 → 摘除 → 插到该题解析区内 `###### 逐项` 标题行前（无则下一题题号前）→ 校验"解析标题行后紧邻图组"清零。

**首次出现原则**：同专题内，同一动图只在**第一次遇到该考点的题目**的解析中完整展示；后续题目遇到同一考点不再重复插。

操作步骤：
1. 自上而下扫描题目，识别每题考点（`custom-qb-question-topic-ids` 或题干主题）
2. 考点首次出现的那道题 → 在其解析区内按上述位置规则插入（逐项标题前，或该选项条目内）
3. 后续同考点题目 → 跳过（不插）

完成判据：同专题内每个考点动图出现次数 == 该考点首次出现次数（无重复展示），且无图行紧邻解析标题行。

### 一图多变（制作侧配合的推荐做法）

同一考点做 2-3 个视角变体，专题内按难度递进使用，避免视觉疲劳：
- 角度1：标准正视图（基础题用）
- 角度2：带参数标注/关系分析（进阶题用）
- 角度3：极端情况/边界条件（难题用）

插入规则：考点首次出现→角度1；同专题第二次遇到→角度2；第三次→角度3。变体不足时按 missing-animations.md 补做。

### 真金题思源文档

- 题目区：**题号N末块**锚（下一题标题前的块），previousID 插入
- 考点必背区：小节标题锚
- 刑法讲次错位表：动画04主体↔真金题03、05行为↔04、06结果↔05、07因果↔06、08主观↔07、09排除违法↔08、10排除责任↔09、11形态↔10、12共同犯罪↔11、13罪数↔12、14体系↔13、15裁量↔14、16执行↔15；02犯罪构成/03犯罪客体无对应讲

## 二、闪卡 —— 按知识点插入卡背面（2026-09-01 用户纠正后的铁律）

闪卡块结构：`- 问题 #标签#` → 缩进答案行 → `{: custom-dm-... custom-dm-card-id="..."}`（IAL 行=卡尾，卡背面=IAL 行**之前**）。

1. **图必须插在卡背面：卡内容末尾、该卡 IAL 行之前**（图行下方跳空行后最近的 IAL 行 = 它所属的卡）。插在 IAL 行之后=两卡之间的间隙（不渲染）；插在 `# ⚡标题`/`### 小节` 下=制卡范围外（不渲染）——**两者都绝对禁止**
2. 场景 title ↔ 卡片正/背面知识点语义匹配；对不上卡的场景从文件头顺延铺进各卡背面（每卡 ≤2）
3. 卡片块的 IAL（custom-dm-card-id）可作唯一定位锚；严禁把图插进 IAL 行中间（会把 IAL 拆断）
4. 文件 ↔ 动画映射：文件名"NN 专题N 标题-闪卡" ↔ 讲义动画 ref 的专题标题（按标题关键词）
5. 闪卡有严格校验器：只增不改，插完跑 validator
6. **历史事故**：2026-09-01 发现全科目 1013 图插在卡外间隙/标题区（不渲染），已脚本批量归位（6ec54fe，diff 增删对称）；配方以本条为准

## 三、覆盖审计配方（"某文件/科目为什么看不到动画"）

1. 全库按科目统计 `20-整理/**.md` 与 `30-闪卡/**.md` 的 animation-avif 计数 → 缺失文件清单
2. 现存动画按 sourceReference 科目分类 → 该科目可用动画与其专题标题
3. 文件 ↔ 动画按标题关键词生成分配清单（JSON）；映射不上的文件记为**缺动画**（走 missing-animations.md）
4. 注意思源端与 md 端分开审计：思源有内容的文件 md 无动画是落点铁律的正常结果
