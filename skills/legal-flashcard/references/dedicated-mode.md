# Dedicated-card mode

Read this file only after the user explicitly requests flashcards. First invoke the separately registered `legal-marknote` skill by name, then read [marknote-integration.md](marknote-integration.md) and, when a source note or source range exists, [style-inheritance.md](style-inheritance.md). This is a stricter output contract layered on top of `legal-marknote` or `legal-goldquest`; those skills remain the source of truth for legal formatting and question preservation.

## Deterministic workflow

1. Establish the source range, source key, known providers, existing cards, source knowledge tags, flashcard priorities, and any explicitly requested card budget. Calibrate priority only after comparing the complete candidate set under [priority-calibration.md](priority-calibration.md); never use P2 as the default for an unexamined rule. When the user requests a file, path, export, or saved deck, resolve its destination and source-derived filename/H1 by following [naming-and-placement.md](naming-and-placement.md). Resolve atomic note-topic IDs by following [topic-resolution.md](topic-resolution.md), including the broad-provider guard: distinct recall axes require distinct confirmed child providers. Completion criterion: every source range has one atomic topic ID or a named mapping gap, every accepted range has a source-grounded knowledge tag and exactly one source-relative priority with a ledger reason, the P1-P4 distribution has been audited, and any requested file has a recorded dedicated destination plus source-derived filename/H1.
2. Build the source-fact ledger from [card-design.md](card-design.md) before drafting. Include each independently testable rule, fixed list, distinction, exception, trap, date, case-derived new rule/application, and source-written mnemonic, including facts found only in examples or answer explanations. Do not make cards from an original case narrative, party names, chronology, or question stem. Never copy an exercise front or option replay into a card; if the exercise contributes a reusable rule, rewrite it into a party-neutral front and record the case as evidence only. Otherwise record `case-narrative` and reject it. A `案例分析`/`> [!QUESTION]`/习题/真题 block is evidence only, never a card target. If a source range is already cardified (`custom-dm-*` attributes or `#闪卡/优先级/P#` tags), do not re-card it and strip those markers completely from any prose kept in output (`E087`). Completion criterion: every fact has one source locator, recall axis, provider, tags, and disposition slot; every case range has either a reusable extracted proposition with a neutralized front or an explicit `case-narrative` rejection; nothing is silently omitted because it appeared late in the source.
3. Run source grounding and build the provider-scoped source-style map required by [style-inheritance.md](style-inheritance.md). If a `20-整理` note is present, first complete the forced-export route in [siyuan-export.md](siyuan-export.md); do not use its unstyled Markdown as the visual authority. Every answer, citation, cloze target, mnemonic segment, and inherited style must be traceable to supplied material. If the authoritative export is genuinely plain or its foreground palette is sparse, invoke `legal-marknote`'s rich visual contract to create a role dictionary with at least four semantic foreground colors and three background signatures; never satisfy the gate with arbitrary recoloring of two words. Mark uncertain statutes, dates, exceptions, and cases as `待核实`; do not fill them from memory. Completion criterion: every ledger fact has a source locator or blocking note, every candidate range has an exact export-backed style map or an explicit MarkNote style plan, and any unresolved export gap is reported before card drafting.
4. Draft candidates by applying the recall-unit gate in [card-design.md](card-design.md). For every non-simple back or source range containing ordered steps, nested rules, a substantive Callout, true comparison table, recall-sized diagram, or a useful relation to a sibling card or easily confused doctrine, read [answer-structure.md](answer-structure.md) and inherit or select the matching carrier. Treat mnemonics as candidates even when the source never writes 口诀: a compact inline-code sequence (`` `国有城土海水矿` ``), a memory Callout (TIP with 记忆/口诀/联想/谐音/取字/首字), or a 谐音/缩写/首字 mapping is an implicit mnemonic and becomes an `mnemonic` card (`W128` flags the omission). Run the clause split before rendering: long or multi-clause answer lines become a governing parent with source-shaped children unless the proposition is genuinely inseparable. For a procedure, chronology, priority, or source-significant sequence, use ordered `1.` children; do not flatten it into peer bullets. For medium or complex relations involving process, branches, role mapping, comparison, or many-to-one structure, generate or inherit at least one Mermaid carrier unless a source-shaped table or image is the materially better primary carrier; a plain list-only answer is a warning requiring disposition. Run the Callout selection pass separately: route a whole warning/exception/trap through a Callout root, and isolate a local exception, decisive boundary, conclusion peak, or memory relation in a nested Callout after a list card's direct answer. A Callout must add value — state the boundary, exception, trap, or reasoning in new words; a Callout that merely repeats the direct answer text fails `E095`. When the user requests a question-side diagram or a complex process, branch, role relation, or many-to-one mapping materially benefits from a retrieval skeleton, read [question-side-mermaid.md](question-side-mermaid.md); keep that branch limited to `basic/list`. Split definition, composition, status, policy, condition, procedure, exception, legal effect, distinction, and historical source when independently gradable. Completion criterion: every candidate has one expected-answer statement, one semantic kind, one stable parent/variant identity, and a source-grounded answer structure that exposes rather than flattens its legal relation; rich Callout coverage reaches at least one card in six and every explicit exception/trap/confusion cue has a Callout decision; every added memory link is inside the back after the direct answer and names a traceable target plus relation axis; any front visual passes its separate boundary and leakage gate, every case-derived front is neutralized or rejected, and every eligible complex relation has a Mermaid, inherited image, or documented carrier exception.
5. Compare existing card IDs, normalized fronts, expected-answer statements, and answer fact sets within the same source range. Reject a summary that only unions accepted answers as `duplicate-summary`; retain a summary only when it tests a new relation, contrast, application, or source-written mnemonic. Completion criterion: every candidate has one accepted or rejected disposition from [validation.md](validation.md), and no accepted pair has equivalent prompts and expected answers.
6. Render accepted cards using [card-design.md](card-design.md) and [protocol-contract.md](protocol-contract.md). Default to `basic/list`: write the question directly as the root list item, end it with `？` or `?`, and write direct answer children without labels. Keep the front short — a question or mnemonic cue within about 70 visible characters (`E092`); when the front needs context, use `<br />` line breaks or a text-block Callout inside the same list item. A cloze/mark card is front-only: never put a bare sub-list under it (a sub-list is parsed as the back card, `E093`) — if a sub-list is needed, wrap it inside a Callout (a `> [!TIP]` block containing the quoted items) so it stays on the front. Use `cloze/mark` for one short deletion and `mnemonic/list` for an exact source-written cue with an auditable mapping. Use `blockquote` when quotation semantics require it. For a `callout` root, put the complete plain-text question in the directive title itself; the title is the DAMO front and the body is the answer. For a nested Callout inside a list card, keep the direct answer first, indent the Callout into the answer sub-list (deeper than the direct answer items), then use a plain title naming the exact boundary or relation. Keep all color, highlight, bold, italic, strike, code, and underline styles in Callout bodies. When the source range carries a Markdown diagram (`![...](...)`), copy it onto the card back beneath a governing answer child; a card whose source range has a diagram but whose back drops it triggers `W126`. Emoji is per-card: every non-simple card carries at least one semantic emoji beyond `✅/❌` (`E090`), the deck keeps overall coverage above 80% (`E091`), and a card that uses emoji places one on both the front and the back (`W127`). Anchor emoji to the specific legal concept (🚚 指示交付, ⏳ 自动续期), not to generic cue words (注意/重点/要点/考点, `W129`); keep each emoji below 9 uses per deck (`E094`), and never derive emoji by scripted word replacement (`E130`) — emoji placement is hard-gated: sentence-end piling (`E131`), line-head label bunching (`E132`), and floating icons with no neighboring concept (`E133`) are failures, so put each icon tight beside its term, mid-sentence or at the concept A card's front and back must not reuse the same emoji (`E100`): the front emoji marks the question's subject, so the back needs a different emoji anchored to the concept the answer actually marks (front `💪 支配权的概念是什么？` → back `🛡️ 绝对权`, not another `💪`). Put knowledge and priority tags on the root front/cue line (or the separate quoted line beneath a root Callout title), then attach the complete IAL to the container root on one physical line. Knowledge-tag segments must be stable source-named concepts, never position labels: `专题二`/`第19讲`/bare numbers in the tag fail `E101` (rename `#法考/民诉/专题二/诉的分离#` to `#法考/民诉/诉的基本理论/诉的分离#`; the filename and H1 sort prefix stay as-is). Completion criterion: no generated item begins with `问题：` or `答案：`, every basic front ends in a question mark, every Callout title is plain, every root Callout title is a complete question, rich coverage reaches the required count, and each card matches one normative kind example.
7. Apply the MarkNote adapter and source-style map, then run `scripts/validate_flashcard.py <draft.md> --source <source.md> --require-report --rich-style` for medium/complex dedicated decks. **Strict gates are the dedicated-mode default**: `--require-report` and `--rich-style` are on without any flag; relaxed mode requires the complete manual relaxation set `--no-require-report --no-rich-style` together (one alone exits with a usage error). When the draft exists only in working context, pipe it to `scripts/validate_flashcard.py - --require-report --rich-style`; lack of a saved draft is not a waiver. Manually preview each card front in isolation before reading its back; verify the expected answer is specific, the prompt does not leak it, the card is not a summary duplicate, the style is not a two-signature patch, and every eligible complex relation has a visual carrier decision. Then audit the palette as a sequence and as a deck: preserve stable colors for recurring terms, diversify adjacent cards through other grounded roles or ordering, and rebalance dominant colors without decorative recoloring. If no explicit budget was supplied, keep all valid covered candidates; do not use `over-budget` as a convenience filter. Apply an explicit budget only after this pass. Completion criterion: the checker exits 0, no `E` finding remains, every `W` finding has a keep/revise/split/reject disposition, low style diversity and missing eligible Mermaid warnings are either revised or explicitly justified by the source, adjacent cards and the deck-wide foreground distribution pass `E080`/`E081`, every highlighted cloze/mnemonic span and every color/background fragment is source-grounded or covered by the approved MarkNote style plan, every ledger row has a final disposition, and the report reconciles candidate, accepted, and rejected counts.
8. Produce a clean delivery: H1, source-derived grouping headings only when useful, accepted card containers, one final parseable YAML report/provenance block, and no prose report or source footer. Keep the source-fact ledger, source key, provider budget, tag rationale, card-kind mix, style audit, and rejection details in working context. Do not call Riff or mutate runtime state. Completion criterion: the YAML block reconciles candidate/accepted/rejected counts and rejection reasons, `report.priorities` lists the P1-P4 counts and sums to `report.accepted` (`E088`), it contains `source.note` and `source.protocol: DAMO 闪卡 schema 1`, is the final nonblank block, and deleting the cards plus YAML block leaves only the H1 and useful source-derived grouping headings, with no audit preamble.

## Rendering rules

- Basic cards use one direct question as the first list-item paragraph and an unlabeled semantic back structure beginning with its child list. Follow [answer-structure.md](answer-structure.md) for answer-side nested lists, tables, Mermaid, and source-container inheritance. Follow [question-side-mermaid.md](question-side-mermaid.md) only for an eligible front retrieval skeleton. Attach the card IAL to the complete root block, outside any table row or code fence.
- Reuse source-styled fragments exactly within their provider range. A plain source range may remain plain; do not color a question or answer merely to make every card look uniform.
- Cloze cards use `==明确关键术语==` as the deletion target. Keep the cloze short; never highlight an entire conclusion sentence.
- Mnemonic cards do not require a fake question. Put the complete source-grounded口诀 or cue in a visible `==...==` highlight. When each sentence contributes a character or segment, highlight the complete口诀, the corresponding character/segment in every source sentence, and the assembled result; retain the mapping order. Use a child list for the sentence-to-character mapping when it improves auditability.
- A blockquote or callout must carry a substantive property (for example an exception or warning), not decoration.
- Preserve existing mark cards. Do not rewrite them as basic/list cards.
- A new variant ID is `<parent-business-id>-<stable-variant-key>`, such as `-recall-v1`, `-cloze-v1`, or `-mnemonic-v1`. Preserve existing stable IDs; variants share the parent prefix and never use a block ID, Riff ID, or database row ID.
- `custom-qb-note-topic-id` is the card's one narrow atomic provider ID. If a broad file-level ID is the only direct attribute, first perform the self-completion workflow in [topic-resolution.md](topic-resolution.md); stop with `missing-topic` only after the confirmed catalog, sibling multi-provider patterns, and source headings fail to establish a stable mapping. Never attach the broad ID to every card merely to pass validation.
- Keep tags as visible Markdown content on the root line, never as IAL attributes or detached paragraphs. Preserve the source's knowledge-tag vocabulary verbatim; do not require a particular namespace or hierarchy. Add exactly one priority tag: `#闪卡/优先级/P1#` through `#闪卡/优先级/P4#`; keep priority separate from knowledge tags. Assign priorities relative to the source range under [priority-calibration.md](priority-calibration.md); P2 is not a fallback, and more than half the deck in P2 is the `E089` hard failure. If the supplied material provides no source-grounded knowledge tag, report `missing-tag`; if no priority can be justified, report `missing-priority` instead of inventing one.

## Clean delivery

Default footer with no rejection:

```yaml
report:
  candidates: 6
  accepted: 6
  rejected: 0
  rejection_reasons: {}
  priorities:
    P1: 2
    P2: 3
    P3: 1
    P4: 0
source:
  note: "客观/02-背诵卷/理论法/2026-马峰/20-整理/02-考点25-宪法的制定"
  protocol: "DAMO 闪卡 schema 1"
```

Footer with rejection:

```yaml
report:
  candidates: 8
  accepted: 6
  rejected: 2
  rejection_reasons:
    duplicate: 1
    missing-topic: 1
  priorities:
    P1: 2
    P2: 3
    P3: 1
    P4: 0
source:
  note: "客观/02-背诵卷/理论法/2026-马峰/20-整理/02-考点25-宪法的制定"
  protocol: "DAMO 闪卡 schema 1"
```

`report.priorities` states how many accepted cards carry each of `P1`-`P4`; the four counts must sum to `report.accepted` and match the cards' actual `#闪卡/优先级/#` tags (`E088`).

Do not precede the cards with a source/protocol/style manifest. The combined YAML report/provenance block is the only default provenance note and must be the final nonblank block. Supply expanded provider allocation, style audit, or rejection diagnostics only when the user explicitly asks for them, and keep such diagnostics outside the saved flashcard Markdown unless the user asks to embed them.
