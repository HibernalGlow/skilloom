# Legal Flashcard

Use this skill as a mode router. Card generation outputs portable Markdown semantics and never writes Riff runtime state. The explicit SiYuan delivery route may create documents only through the bundled Protyle-paste script.

## Acquire SiYuan source

When the source is one or more `.sy` files, a SiYuan document directory, an offline workspace, a `20-整理` note, or a flashcard footer whose source is ambiguous, read [siyuan-export.md](references/siyuan-export.md) before routing. For dedicated-card mode, resolve and use a fresh export or matching `25-kramdown` snapshot as the style authority; `20-整理` is content navigation only. Run `scripts/export_siyuan_markdown.py` whenever the authoritative `.sy`/workspace source is available, even if a plain `20-整理` Markdown file opens first. **The canonical export/import scripts live in the separately registered `$siyuan-export` skill; this directory keeps byte-identical copies in sync** (modify there or here, then `cp` + `diff`). Keep acquisition read-only and use portable IAL by default; use complete IAL when requested, and emit attribute-free Kramdown only when explicitly requested. Completion criterion: the working source has an authority class and export path, each requested source document has one exported Markdown file or ZIP member, and the source `.sy` files are unchanged.

## Deliver Markdown to SiYuan

When the user asks to paste or import one or many Markdown files into a SiYuan directory, read [siyuan-paste.md](references/siyuan-paste.md) and run `scripts/paste_siyuan_markdown.py` (canonical copies in `$siyuan-export`). An exported `25-kramdown\...\法考\客观\民诉` folder can be passed directly as the source; use the already-existing SiYuan `/法考/客观/民诉` as `--directory`, so the processing folders are not copied. Use `--title` for one explicit title or `--title-map` for batch titles; otherwise prefer the first H1 before the filename. Never replace this route with direct document-content upload when IAL must survive, because the bundled script delegates each write to a real Protyle paste event. Completion criterion: one batch receipt names every created document and its target path, or the failure names the completed prefix and snapshot.

## Revise existing SiYuan cards

When cards already exist in SiYuan and the user requests priority, tag, style, wording, answer-layout, insertion, deletion, or reordering changes, read [siyuan-live-revision.md](references/siyuan-live-revision.md). SiYuan is the authoritative flashcard store: modify its blocks directly with the local `siyuan` CLI (`block update`, `block insert`/`append`, `block delete`, `attr set`) against `$SIYUAN_WORKSPACE`, using `--dry-run` for broad scope, then optionally re-export from SiYuan to overwrite the local `30-闪卡` Markdown mirror. Never reverse-overwrite SiYuan from a local edit (`import md`, wholesale write-back, `.sy` edits); editing the local file alone is allowed only when the SiYuan document is empty or holds only unrelated records. Completion criterion: every write targets a confirmed block ID, special blocks and frozen attributes are untouched, the edited note passes the applicable validator, and the local file is refreshed only by export.

## Route the request

1. Select **ordinary mode** when the request is note organization, summarization, formatting, or repair and does not explicitly ask for flashcards. Read [ordinary-mode.md](references/ordinary-mode.md). If the source provider is broad or incomplete, also read [topic-resolution.md](references/topic-resolution.md) to complete candidate topic mapping; do not load dedicated card rules. Completion criterion: the note preserves its source contract, records only review candidates with narrow topics or named gaps, and contains no formal `custom-dm-*` card IAL or runtime SRS field.
2. Select **dedicated-card mode** only when the user explicitly asks to make, generate, draft, export, or review flashcards/cards. On this route only, invoke the separately registered `legal-marknote` skill by name; do not assume the two skills share a parent directory. Then read [dedicated-mode.md](references/dedicated-mode.md), [card-design.md](references/card-design.md), [protocol-contract.md](references/protocol-contract.md), [marknote-integration.md](references/marknote-integration.md), [style-inheritance.md](references/style-inheritance.md) when a source note or source range exists, and [naming-and-placement.md](references/naming-and-placement.md) when a file, path, export, or saved deck is requested. If the authoritative export is genuinely plain or its provider palette is sparse, read legal-marknote's rich visual contract and build a semantic augmentation plan before drafting; a sparse export is a trigger to create a documented role dictionary, not a reason to repeat one source color. For medium/complex decks, the GoldQuest rich visual floor is mandatory: carry over provider-scoped styles, actively color every substantive answer line, keep repeated concepts and aliases on stable role colors, color every recurring role/concept occurrence consistently, and use the rich carrier/style plan with `--rich-style`; a deck that only reaches the per-card `E047` minimum is unfinished. Run a Callout selection pass from [answer-structure.md](references/answer-structure.md): use a callout root when the whole retrieval unit is a warning/exception/trap, and use a nested answer Callout when a list card contains a boundary, conclusion peak, or memory relation; the nested Callout must be indented into the answer sub-list (deeper than the direct answer items) or be written as a normal sub-list item (`E086`). `E074`/`E075`/`E076`/`E080`/`E081`/`E084`/`E085` rich errors, `E078` sequence-carrier errors, `E079` case/exercise replay errors, `E089` P2-default flood, `E090` per-card missing semantic emoji, `E091` sub-80% deck emoji coverage, and `E095` Callouts that merely repeat the direct answer must be repaired; `W110`, `W116`, `W117`, `W125`, and `W127` (front/back emoji balance) remain review findings. Completion criterion: every source fact has a disposition and every accepted card has one scoring axis, a normative card-kind container, stable identity, source grounding, narrow note-topic provider, provider-scoped source-style inheritance or an explicit MarkNote style plan, every substantive answer line and recurring role occurrence passes the GoldQuest color-density rule, Callout-eligible semantics and deck coverage pass their gates, adjacent cards have sufficiently distinct palettes, deck-wide foreground usage is balanced, every sequence uses an ordered carrier, every case-derived card has a neutral reusable front or is rejected, and (when a file is requested) a source-derived title, filename, and dedicated destination exists, or generation stops with a named gap.
   - **Palette priority**: in rich dedicated output, color-table labels are soft cues. A plain/sparse/monochrome source triggers a local palette plan; do not repeat one generic concept color across the deck. Before drafting, reserve at least four distinct foreground roles (six for a medium/large deck when the source palette permits), keep any one color below the validator balance ceiling, and repair `E080/E081` before delivery. Preserve intentional source cues, but use other source-approved roles for distinct relations.
3. If the request mixes both modes, finish ordinary organization first and run the dedicated route only for the explicitly selected material. Completion criterion: the output labels the two result sets and no ordinary highlight is silently promoted to a card.

## Shared hand-off

For dedicated rich cards, treat the color table as a soft semantic hint. Build a local palette from the current relation: `概念` is not a color assignment, and a concentrated source hue must not be propagated to every repeated term. Reserve four distinct foreground roles (six when the deck has eight or more cards and the source supplies enough styles), keep one color from becoming the visual default, and use backgrounds or auxiliary styles for a second dimension. Preserve intentional source cues, but use other source-approved roles for distinct legal relations and repair any `E080/E081` palette concentration before delivery.

- Treat the source range, existing cards, topic map, and requested card budget as inputs. Do not infer missing IDs, legal exceptions, dates, or source boundaries.
- Resolve incomplete provider maps before card drafting. The agent should self-complete from confirmed repository providers and existing multi-provider mounting patterns; only an evidence-backed unresolved mapping becomes a reported gap.
- Emit the final generation report and provenance as one parseable YAML fenced block (`report.candidates`, `report.accepted`, `report.rejected`, `report.rejection_reasons`, `report.priorities` with P1-P4 counts, `source.note`, `source.protocol`), never as prose count or source/protocol sentences.
- Build the source-fact ledger, then draft candidates before acceptance. Apply `python -X utf8 scripts/validate_flashcard.py <draft.md> --source <source.md> --require-report` when the source is a file; omit only `--source` when no source file exists. **dedicated 模式默认严格**：`--require-report` 与 `--rich-style` 默认开启（中等及以上牌组必须满足丰富视觉契约，报告必须存在）；宽松模式只有手动传齐全部宽松参数 `--no-require-report --no-rich-style` 才启用，缺一即退出码 2 拒绝运行。验证报告默认封顶 40 条并附 `SUMMARY` 按码计数行，防止大文件审计撑爆上下文：`--code E041` 只看指定错误码（可重复传）、`--all` 解除封顶；退出码始终按全量 findings 判定，与显示过滤无关。Then report candidate, accepted, rejected counts and rejection reasons. Completion criterion: every ledger row has one disposition, the report reconciles to the candidate records and accepted cards, and the source-aware check passes whenever a source file exists.
- **Gate failures are fixed by direct per-site edits, never with fix scripts; never read validator source.** Repair each `E`/`W` finding by editing the offending card text in place, then re-run the validator — the error messages state the standard and the fix. **Under no circumstances open, grep, or script-read the validator or auditor sources** (anything under the legal-* skill `scripts/` directories, or the `_工具/goldquest-mineru-work/` auditors), including preventive reading before drafting. The only sanctioned sources of gate semantics are this skill's text, its references/, and real validator output; if a message is incomprehensible, report the code and text to the user and wait. Never turn findings into batch-replace, recolor, emoji-insertion, or structure-rewrite scripts, and never exploit a validator blind spot to pass without fixing the content.
- Keep `custom-dm-card-kind` (semantic card kind) separate from `custom-dm-card-renderer` (host container). Schema routing is explicit: read the versioned contract when a schema other than `1` is requested. Completion criterion: no card mixes schema versions or invents future runtime attributes.
- Use the card-unit standard from [card-design.md](references/card-design.md): one scoring axis, one specific expected answer or fixed closed set, a source-shaped back structure, short clozes, source traceability, and non-duplicative sibling variants. DAMO Markdown never emits Anki scheduling fields or runtime state. Completion criterion: the output contains semantic card content only, every complex back preserves its visible legal relationship, and no generated `问题：` or `答案：` prefix appears.
- Never card a case or exercise block (`案例分析`, `> [!QUESTION]`, 习题/真题): treat it as evidence only. If a source range is already cardified (`custom-dm-*` attributes or `#闪卡/优先级/P#` tags), do not re-card it and strip those card-recognizable markers completely from any prose kept in output (`E087`).
- Copy source diagrams onto the card back: when the card's source range contains a Markdown image (`![...](...)`), the card carries it beneath a governing answer child; a dropped diagram is a review finding (`W126`).
- Emoji is a per-card semantic index, not decoration: every non-simple card needs at least one semantic emoji beyond `✅/❌` (`E090`), overall rich-deck coverage must exceed 80% of cards (`E091` — simple cards are the only tolerated minority), and a card that uses emoji should carry one on both the front and the back (`W127`). Anchor each emoji to the specific legal concept inside the knowledge point (`🚚 指示交付`, `⏳ 自动续期`), placed directly on the word it marks — one emoji per parallel concept (`简易交付🚚、指示交付📦`) — not to generic cue words like 注意/重点/要点/考点 (`W129`); keep the same emoji below 9 uses per deck (`E094`). **Emoji placement and batch insertion are hard failures, not advisories**: scripted word replacement (same emoji+word pair six or more times) fails `E130`, sentence-end piling (≥70%) fails `E131`, line-head label bunching (≥70%) fails `E132`, and a floating icon with no neighboring concept word (≥50% of deck emoji) fails `E133` — each icon must sit tight against its term (词前或词后紧贴概念词), never as loose decoration. **Never reuse the same emoji on a card's front and back (`E100`)**: duplicating one marker is the lazy way to fake the front/back cue — the front emoji marks the question's subject, so the back must anchor a different concept with a different emoji (`- 💪 支配权的概念是什么？` needs a back emoji like `🛡️ 绝对权`, not another `💪`).
- Mnemonics are not only text labeled 口诀: an implicit mnemonic — a compact inline-code sequence, a memory Callout (TIP with 记忆/口诀/联想/谐音/取字/首字), or a 谐音/缩写/取字 mapping — must also become an `mnemonic` card with a highlighted cue and decoded segments (`W128` warns when the source carries mnemonic material but the deck omits it).
- Keep card fronts short: a question or mnemonic cue stays within about 70 visible characters (`E092`), and extra context belongs on the back, or on the front as `<br />` line breaks or a text-block Callout inside the same list item. A bare sub-list on a front-only card is parsed as the back (cloze/mark cards are front-only, `E093`) — if a sub-list is genuinely needed on a mark card, wrap it inside a Callout (a `> [!TIP]` block containing the quoted items) so it remains front context.
- Vary colors across adjacent back lines: three consecutive lines dominated by the same color fail `E096` — different semantic roles on neighboring answer items should switch colors (or add a background) so the palette stays a readable index instead of a wash.
- Split long back items semantically, like MarkNote/GoldQuest: when an answer line or a nested sub-list item exceeds about 42 visible characters or joins several clauses, split it by semantics (not by punctuation alone) into a governing parent plus deeper child items; steps/procedures/sequences use ordered `1.` children. A flat long item fails `E097` — flat backs full of long lines are unfinished.
- Callouts need a blank line before them: every Callout directive must be preceded by a blank line (or the start of a block, another quote line, a heading, or a fence boundary), otherwise it is parsed as continuation text and not recognized (`E098`).
- A list item's text must not begin with an ordered-list marker: `- 1. …`, `- （1）…`, `- ① …`, `- 1、…` are read as a nested ordered list and misrecognized — remove the leading marker, or write each numbered branch as its own indented real `1. …` child line (`E099`).
